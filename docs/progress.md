# Benchmark Progress

[T15 — Benchmark Evidence Storage](roadmaps/t15-benchmark-evidence-storage.md)
introduces local raw artifacts and committed summaries. New benchmark commands
follow the [artifact contract](benchmark-artifacts.md): full gate, goal and
sweep reports stay in the main checkout's ignored `.bench-artifacts/`; the
calling checkout stores concise summaries with exact raw hashes and recorded
local verification times. Existing historical reports remain unchanged.

[progress/index.html](progress/index.html) charts every closure below over
time: work counters, wall clock, population, lineage, memory sensitivity,
mutational neighborhood, and indicator coverage, read from the same reports.
Its Goal worlds tab follows each baseline world separately over closure order —
population, births, mean energy, lineage, memory, drift against its floors,
neighborhood, structure, typed eat share, blocked moves, per-case work counters
and wall clock, plus a population-trajectory overlay by closure — and marks
every closure where that world's recipe inputs changed. A reading a report did
not measure is drawn as "not measured", never as zero.
Browsers block `fetch()` under `file://`, so serve the directory first:
`python3 -m http.server 8000 --directory docs/progress`, then open
`http://localhost:8000/`. New closures appear automatically once
`benchmark-series.json` lists their summaries. The page also reads historical
full reports and labels unavailable detail; it never fetches a local raw path.

The `[full readings]` links below point into each spec's Performance and Goal
Impact section, which carries the predeclaration, the verdict, and any user
decision. Where a feature's full comparison tables were relocated on 2026-09-09,
that section links on to `progress/readings/<id>.md`.

T11.F06 counter interpretation: `graph_relax_iters` now records entered
nonempty single-evaluation graph visits, including unaffordable attempts.
Historical reports counted relaxation passes; retained raw deltas across this
boundary are not like-for-like work efficiency. The new goal-only
`temporal_memory_sensitivity` component (`temporal-memory-v1`) separately
perturbs previous slots, persisted outputs, and operator state by zeroing and
one-position rotation within each vector. Its boundary is hypothetical
cognition from final committed graph state with final sensors and both memory
versions fixed; no world tick or shared-memory snapshot/decay occurs.


`mesh-execution-v1` counts mesh nodes, distinct dispatched nodes over the
80-execution neighborhood battery, and actual `MaxHopsReached` endings.
Input-route variation compares selected target-position sets only across the
48 independently reset snapshots. `static-successor-bypass-v1` separately
removes each executed node and redirects through its zero-runtime-score
production winner; a knockout counts only when the complete fresh battery's
action queues, including direction and payload, remain identical. It does
not imply ecological neutrality. Founder generation is zero; sampled
generations are actual lineage depths, and per-seed median/max cover all
final living creatures, with the upper median for even populations and
`Undefined` for extinction. Historical missing readings remain unmeasured.
The research note's whole-population 48-snapshot census is a different sample
and battery; these first bounded readings are not an improvement comparison.

`drift-depth-v1` is a goal-only mutation walk, measured once per report outside
world seeds. A generation is one unconditional production birth step,
including zero-applied and behaviorally dead offspring; it is not an
ecological survival step. Checkpoints 0/22/250/1,000/2,000 pool all 50 mesh
readings, using the existing 80-execution battery and static-successor
knockouts. Fresh births sample the first 20 lineage indices, 100 each.
Changed/all-birth fractions include zero-applied births in the denominator
and exclude the separately reported dead class. Each checkpoint retains
integer totals, lineage and execution denominators, requested/applied birth
buckets, conditional tallies, and all-birth class fractions. Historical and
non-goal readings are `Undefined`; unrun timing is null. The complete
[T11.F16 baseline table](specs/roadmap/t11-f16-drift-depth-indicator.md) defines
the depth-1,000 and depth-2,000 no-regression components; T11.F17 owns their
first floors. Mutation-only depth is not evidence of ecological persistence
or cognition.

`drift-depth-v2` adds only the executed-target stand-in that T11.F17's policy
needs; sampling, checkpoints, battery, and every field of v1 are unchanged, so
v1 rows remain the baseline. The executed set comes from the same battery hop
records (`mesh-execution-v1`) as node ids, recorded in the reading's
`executed_source`. Its cadence is recorded in `executed_refresh`: the walk
refreshes each lineage's set at depth 0 and every 10 generations, so that a
checkpoint's rows do not depend on which checkpoints precede it, while the
fresh births at each checkpoint derive their own set from the parent they are
drawn from. Between walk refreshes, removed nodes drop out of the set and
added nodes wait for the next refresh. Reports written before this version
read as v1 with both metadata fields empty.
