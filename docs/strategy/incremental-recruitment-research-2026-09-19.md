# Incremental recruitment: from preserved behavior to cumulative adaptation

**Date:** 2026-09-19 (America/Los_Angeles). **Status:** reviewed research; T13.F07–F10 added to the live roadmap on 2026-09-19; no production implementation or new experiment campaign executed here. Source inspected at `45c8063722fa3aa509a32d523f5e477e9fcd3853`, including pre-existing uncommitted aging changes. The accompanying [evidence audit](incremental-recruitment-research-2026-09-19.evidence.json) records source and artifact identities. This report supersedes neither historical measurements nor accepted feature exceptions.

## Executive conclusion

Petri has made it easier to preserve a working controller while adding structure. It has **not demonstrated a reliable evolutionary path from that structure to an additional, retained function**. The strongest diagnosis is a mismatch between the units that mutation creates, the contexts in which computation becomes expressed, and the units on which selection can act. A harmless detour is not necessarily one small mutation away from a useful action. An expressed copy is not necessarily a specialization. A large population is not necessarily producing successful replacements.

There are at least three interacting constraints, rather than one proven universal cause:

1. **Accessibility and expression:** acquiring inputs, useful computation, an effect, and a winning route often requires several coordinated changes. The prepared-versus-unprepared T13 assay sharply exposes this gap, but does not identify a unique architectural remedy.
2. **Locality and retention:** a payload change can affect every context using the module; stored growth also increases mutation supply and costs. Under biased targeting, dormant growth can increase damage to an unchanged active controller.
3. **Ecological opportunity:** aging, reproductive affordability, resources, and bottlenecks determine whether a candidate has enough descendants to be selected. These can prevent cumulative adaptation even when the controller can express it.

The recommendation is **contextual duplication with measured specialization**, pursued as a continuation of T13. First measure the missing transitions under the current mutation policy. Then compare a narrowly restricted direct contextual copy against regulation-first same-target aliases followed by fission. Prefer the direct copy provisionally because it uses fewer evolutionary steps and closely extends existing operators. Aliases must earn their extra mechanism by reducing preparation cost enough to improve retained recruitment. Neither is yet a production winner.

The proposed general alias mechanism is rejected: arbitrary same-target gate drift can steal another destination's contexts; new node identities can alter visited-node scheduling; and unchanged actions do not imply unchanged energy or fitness. The safe experimental domain is an already executing Graph predecessor with one destination, in an acyclic mesh, followed by a pure feed-forward Graph action module. The current canonical founder's Graph→VM edge is **ineligible**. That limitation is a testable risk, not a reason to count hand-prepared starts as emergence.

The target is ordinary mutation producing new nodes whose specialized computation improves performance, preserves incumbent competence, and remains useful in reproductive descendants, with actual costs and without rewarded complexity. If founder decomposition and existing operators already achieve this, stop before adding another operator.

## Causal model of the failure

Think in conditional transitions, not total node count:

`births → requested events → applicable operator/site → preparation survives → context is expressed → useful local change → reproductive advantage → retention → specialization and reuse`

A bookkeeping approximation is `expected recruits ≈ births × q(eligible preparation) × q(expression | preparation) × q(benefit | expression) × q(retention | benefit)`. These factors are not independent and must be estimated conditionally from recorded histories; this is not a fitted population model. A bottleneck at any factor can leave abundant mutations and many nodes but almost no cumulative adaptation.

| Transition | Petri-specific mechanism | Discriminating observation |
| --- | --- | --- |
| Supply → applicable edit | Binomial supply grows with all stored units, then topology versus internal domains, operators, applicable nodes, sites and values are selected | Requested/applied counts by operator and target; payload units changed; rate of edits to the candidate's gate/payload per birth. A high aggregate changed-birth fraction cannot substitute. |
| Preparation → persistence | Aliases, route edges, clones and gate wiring carry structural cost before any improvement | Creation-to-deletion/extinction time, charged energy, reproduction cost and probability of another relevant edit before loss. Distinguish cost selection from lack of targets. |
| Preparation → expression | An empty graph may pass through; an action needs a positive gate; route and direction choices use hard maxima | Action-gate margins, route winner share across contexts, missing input/effect surface, finite/nonfinite values, termination and queue-cap outcomes. |
| Expression → benefit | Copying a working module can preserve output but does not supply a better output for the new context | Clone-to-ancestor replacement at the same route, paired with gain over the starting controller and incumbent-context performance. |
| Benefit → ecological selection | Benefit must affect applied food intake, movement, successful offspring and their reproduction under actual costs | Parent/newborn/first-breeder cohorts and matched-state counterfactuals; aggregate food stock and final census are insufficient. |
| Selection → retention | Further mutation can erase policy, regulation or the module; bottlenecks can lose carriers | Competing loss causes, descendant depth, shared ancestry, copy provenance, active-policy damage versus stored size. |

Under current production supply, `E[M] = Gp`; for `p=.005`, G=111 gives 0.555 requested events, G=600 gives 3.0. `P(M=0)=(1-p)^G` is about 57.3% and 4.94%, respectively. Neither an event nor a changed action is necessarily deleterious. With execution-biased selection, increasing G without changing the active core can nevertheless raise that core's absolute edit exposure. A reduced global rate changes both harmful edits and scarce useful edits; it cannot identify which transition failed.

Context isolation aims to reduce pleiotropy: a change in the copy should affect only the situations assigned to that copy. It does not make an arbitrary discrete action mutation beneficial, guarantee balanced context partitions, or protect the gate from later damage. Selection can also find a simpler single-node policy that solves both tasks. Such a result is a success for adaptation and evidence against requiring mesh growth for that task.

## Restricted mechanism to test

### Eligibility and transformation

For the first candidate, require an already-entered Graph predecessor P with exactly one target entry (`targets.len() == 1`) naming a valid A, a free gate slot not written anywhere in P's backend, and a **whole reachable mesh DAG**. Require A to be a pure feed-forward Graph module with at least one existing action effect. Exclude self/forward compute references, stateful compute kinds, previous-output dependencies, graph-local state, plasticity and eligibility traces. Preserve input references, output-slot conventions, outgoing continuation, action-bank order, terminal behavior and one-of-two dispatch. No ancestor or downstream path may separately visit both alternatives. Reject invalid candidates atomically with an explicit reason. Structural eligibility uses `enters_visit()` and genotype predicates; actual dispatch frequency is recorded separately and never chosen by a fitness battery. At later fission, revalidate P as exactly two entries naming the same A, with distinct independent slots and no third or dangling destination; revalidate mesh DAG and A purity after all intervening mutations. Fission needs no third free slot. A topology/state change that invalidates this predicate makes fission inapplicable, not silently safe.

Initially restrict the new gate to one read-only edge from an already available P input/source, with a sampled weight/bias under a predeclared distribution. Do not insert a compute node, redraw sensors until useful, fit a gate to the assay, or make an empty predecessor start computing under a preservation label. Allow existing ordinary input mutations in later generations. Both branches begin with the same computation; balancing their winning contexts is measured, never rewarded or forced by oracle.

**Direct copy:** make A′ with A's genome payload and continuation; append an independently gated P→A′ alternative while preserving P→A's order and score. Only one alternative executes. **Alias:** append P→A with the independently gated entry; gate edits can vary the winning entry. **Fission:** clone A at birth and retarget only that alias to A′. This needs no runtime copy-on-write pointer, shared mutable backend, or persistent alias class. Route entries already name NodeIds. Diagnostic provenance is separate from semantics.

There are two distinct equality claims: (a) dispatch/payload equality under the same runtime inputs and available energy, modulo A/A′ identity; (b) the complete applied tick including structural charges. Only (a) is a candidate invariant. In (b), extra carry cost can change energy sensing, action eligibility, compute exhaustion and later reproduction, so even action equality can fail near thresholds. Measure those failures; do not waive them as floating-point noise. Fission of a recurrent graph additionally changes its state history, hence the initial exclusion.

### Why the general form fails

With scores A=0 and B=1, adding a same-target alias to A at score 2 changes the destination from B to A. With only A destinations, changing which entry wins preserves the destination, but slot sharing or a new predecessor compute visit can still interfere. With a cyclic continuation leading back to A, A′ has a different visited identity; a new path can run both copies or change the available successor. Stateless computation alone does not fix this scheduling difference.

After fission, changing one weight can still cross an action threshold or alter a discrete direction for an entire context. A rare or empty context supplies too little selection; a broad context retains pleiotropy. Aliases can therefore move the activation barrier rather than remove it. Record gate margins, context prevalence, edit-to-phenotype distance and fission-to-first-improvement waiting time.

An atomic **fission-plus-one-payload-edit** is a separate, conditional experiment, not the default proposal. Consider it only if the cost-visible assay shows neutral clone loss before a payload opportunity while an expressed clone can improve. Sample exactly one applicable local field/edge edit without evaluation, retries or knowledge of utility; count both structural and payload edits. Compare fission alone at equal mutation opportunity and work. Function-preserving macro-mutations have precedent, but bundling a task-fitted solution does not.

### Causal attribution and identity

Count an alias as a regulatory variant, **not a new node**. Record route-position variation separately from destination variation. Stable observation identity is `(world, lineage, birth event, local NodeId)`; a recycled NodeId is not ancestry. Track creation, copy source, later copies, deletion, extinction and horizon censoring in bounded observation records. Do not use the battery's contributing set to choose production mutation targets.

For a clone, retain three distinct counterfactuals: remove/bypass it; replace its payload with the recorded source payload on the **same route**; and restore the starting controller. Bypass asks whether the node matters at all. Ancestor replacement asks whether its new computation matters. Starting-controller comparison asks whether the lineage improved. Add a routing counterfactual that collapses the context partition while retaining one computation. For a truly de novo node with no copy source, the ancestral payload is its recorded birth payload; improvement over that payload must still preserve incumbent competence. Payload swaps keep destination identity/continuation fixed; report natural-cost and matched-runtime-input comparisons separately because payload size changes charges. Genomes whose losses are explained solely by removing an old indispensable action are not specialized recruits.

### Shared outcomes, exposure and uncertainty

The primary assay success is a new module created after the unprepared start (including starts with an incumbent founder but no prepared future recruit), a gain of at least 1/8 on the added-context task, an ancestor-replacement loss of at least 1/8 on that task, no loss on the original eight incumbent scenes, and useful retention at discovery+64 descendant generations. Follow-up to +16 and +256 reports shorter and longer retention. No discovery by the fixed horizon is a failure in the primary denominator; extinction is a competing loss, not ordinary censoring. Unfinished runs are censored and cannot pass.

Use existing Task A/B definitions as historical controls, but **do not demand simultaneous solutions to conflicting tasks on identical inputs**. The cumulative task must expose an already available context cue: two disjoint, equally represented scene sets, eight each, with frozen desired actions, one retaining the incumbent mapping and one adding a mapping. Freeze cue/source combinations and held-out scenes before candidates are evolved. Use at least two distinct added behaviors (steering and typed eating) in separate assays. The flat spec freezes exact scene tables before the first run; this report defines their constraints rather than inventing untested task rewards. Prepared positives verify capability; they never enter the unprepared success numerator. A simple nonmodular controller solving both sets is a required control and a valid reason not to pursue module growth for that task.

For discovery screens use 64 independent lineages per arm, four batches of 16; two siblings per generation; 256 discovery generations and follow-up through generation 512 so discovery at 256 still has +256 follow-up. Preserve the parent, siblings, selector decision and nonrecruiters. This gives 65,536 proposals per arm, not independent N=65,536. At 0/64 the one-sided 95% bound is 4.57%; 64 is sufficient to reject only fairly frequent discovery, not rare long-term evolution. Compare paired lineages with paired bootstrap or exact paired binary contrasts; report effect sizes and intervals, not just p-values.

The primary practical screen target is at least 16/64 retained specialized recruits from unprepared starts (25%) with a paired 95% interval for improvement above ordinary mutation excluding zero. Only one preselected candidate-versus-ordinary contrast is primary per stage; other comparisons are exploratory, then retested on fresh seeds. No winner is selected from a large matrix by its smallest p-value. After S2–S5 choose one final configuration, run one shared fresh 96-lineage-per-arm replication on two tasks, rather than confirming every explored setting. A direct-copy nomination uses candidate/control (four arms total); an alias nomination uses alias/direct-copy/ordinary (six arms total), with alias-versus-ordinary primary and alias-versus-direct a predeclared secondary comparison tested only after the primary gate passes on both tasks. This is the downstream engineering qualification panel: it is sized for an approximately 25% versus 5% independent success contrast at 90% power under a two-sided 5% normal approximation (about 65/arm), with margin for discreteness and pairing uncertainty. This does not power a 5% difference, a 5-percentage-point noninferiority claim, a 5% reproduction-ratio margin, or a rare ecology event. All noninferiority claims use one-sided 95% bounds and a pilot-based precision/power feasibility check before launch; an interval crossing the harm margin is inconclusive and blocks rollout. A screen point estimate inside the margin is not safety evidence. Re-estimating sample size requires a new prospective panel, not extending until significant.

Record initial/checkpoint/discovery genomes, deterministic mutation seeds, applied edit deltas and per-proposal outcome/selection records sufficient to reconstruct parent and siblings; do not store a full genome for every proposal. A separate two-lineage feasibility pilot must measure time and bytes, replay reconstructed proposals identically, and project the full panel below its caps before launch. It supplies no efficacy evidence and cannot choose favorable settings. F06 raw density would otherwise project roughly 11.4 GB even for the revised S0 panel. A cap failure stops for a prospective budget/design amendment, never drops unfavorable records.

Every stage reports births, requested/applied events, gate/payload opportunities, eligible-site fraction, stage transition times, actual dispatch and contribution, genome p50/p90, carry/compute/action/replication debit, death/reproductive failure, and wall/work budget. Closed-loop finite-population or ecological outcomes use run/world as replicate. Cohort samples and siblings remain clustered. All output/energy ledgers must come from the production runtime and applied action path.

## Non-goals, remaining risks and falsifiers

No promise of cognition, indefinite survival or general open-ended evolution follows. No global novelty reward, complexity reward, automatic reseeding, speciation, function-oracle mutation targeting, fan-out, new learned controller, mutation-rate cure, cost exemption, or production replacement is proposed. Stateful/VM fission, indirect developmental encoding, shared runtime code objects and residual action arbitration are deferred.

The most important unresolved risk is that restricted context partitioning is too rare or not useful in the actual ecology. If ordinary mutation on T18 discovers retained additional nodes as often as either candidate, no new operator is warranted. If equal target-local exposure erases the difference, the repair belongs to supply. If cost-free recruitment works but real-cost recruitment fails, extending retention rather than inventing more wiring is the open problem; this does not authorize a cost subsidy. If copies execute broadly but local edits still cannot improve without breaking incumbents, investigate actuator-level residual or typed composition semantics. If only whole modules or indirect developmental changes can express beneficial increments, reopen encoding architecture with the same locality/retention controls.

A robust single-module policy is not a failure because it uses fewer nodes. Conversely, many copied nodes with unchanged ancestral computation are not success. The claim to establish is that **when an additional context-specific function is useful, ordinary evolution can recruit and retain it without sacrificing existing competence**. The proposed gates can reject this recommendation.
