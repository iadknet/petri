## Question

How hard is it to make Petri's worlds procedurally generated from a saved config and seed, and what set of baseline worlds should replace the current single-world testing seeds?

## Verdict

Small. The world is already three-quarters procedural: fertility is generated from the run seed and the config, food is seeded deterministically over the passable cells, and founders are placed by a seeded shuffle. The one layer that is neither in the config nor regenerated from the seed is barrier terrain, which today exists only through the paint and pattern endpoints after seeding. The five pattern generators (`Maze`, `Spiral`, `Noise`, `ParallelLines`, `Star`) are already seeded, serde-serializable, and produce paint points, so the missing piece is a `world.terrain` list of layers applied inside `seed_simulation` before food and founders. Once that lands, the existing config JSON is the saved world, the CLI and the server already load it, and the config digest already identifies it.

Two things are harder than they look and both are cheap to fix at the start: the clustered `Noise` generator's output depends on hash-map iteration order (recorded as deferred by T10.F11 because patterns never ran on the seeding path), and the generator behind every seeded draw is `SmallRng`, which the `rand` documentation says is not reproducible across library versions or platforms. Neither blocks the design; both belong to the first feature.

The baseline worlds should not replace the goal profile. They should be a small named set of recipes read through the existing sweep profile, with the default barrier-free world staying as the goal profile so the program's indicator series stays comparable. The pressures the world can compose today, with evidence: fragmentation by barriers into connected patches (more, smaller connected reserves maintained and generated more phenotypes in Avida), scarcity and patchiness of fertility, and occlusion, which the sensor contract already delivers from any barrier; the set composes them as well as isolating them (user decision 2026-09-08). Differentiated food, the other lever the literature supports (limited and regionalized resource types drove adaptive radiation, and diversity rose with the spatial entropy of their placement), is not yet a pressure in Petri: food types can be placed apart, but every type pays the same eat reward. T12.F04 makes it one by giving each type its own energy per bite, regrowth, and recovery (user direction 2026-09-08), a tradeoff landscape that foraging theory describes exactly and not the nutrient budget removed on 2026-09-07.

## 1. Problem, constraints, decision criteria

**Problem.** Petri has one production world: 1600 by 1600, barrier-free, one green food type, two Poisson-blob fertility layers, read at seeds 11/22/33. Environmental features (T02, T04, T06) each need a world with the pressure they act on, and the program needs those worlds to be the same from one feature to the next.

**Constraints carried from the program** ([roadmap notes](../roadmap.md#notes-for-ai-agents), [`AGENTS.md`](../../AGENTS.md)): seeded runs reproduce byte for byte across processes and thread counts; production defaults change only with a predeclared epoch re-pin; every mechanism feature names a natural analog and reaches creatures through the world and body; the goal profile runs once per closure and its series must stay comparable; backward compatibility is not a default goal; one workflow, no parallel machinery; KISS over verification machinery (user decision 2026-09-07).

**Decision criteria.** Whether an option reuses what exists (config schema, pattern generators, sweep profile, reproducibility test); whether saved worlds survive dependency upgrades; whether the default trajectory stays unchanged; whether the baseline set adds a bounded, occasional cost rather than a per-closure one; whether each archetype has a natural analog and evidence that its pressure matters.

Facts that shape the design:

- `SimulationConfig` derives serde with `deny_unknown_fields`; `v3-cli run --config` deserializes a full config; `POST /v3/simulation/startup` deep-merges a partial patch over the server's defaults; `GET /v3/simulation/config` returns the effective config. A saved world therefore needs no new format, only a field for terrain and an agreed seed rule.
- `crates/v3-core/src/patterns/mod.rs` exposes `generate_pattern_seeded(bounds, params, seed)` over a serde-tagged `PatternParams` enum with `PatternBounds` in `u16`; the frontend already mirrors the types in `frontend/src/types/pattern.ts` and applies them with a random seed from the pattern toolbar.
- The sensor contract already makes every barrier opaque with line-of-sight ray casting and a strict-corner rule (`docs/reference/v3-sensor-spec.md`, opacity rules), so seeded terrain delivers occlusion with no sensor change. T02.F02's remaining scope is the goal-profile occluded condition, creature opacity, and the sensor-noise treatment.
- T10.F11 (spec Non-Goals) recorded `patterns/noise.rs` as hash-order dependent and out of scope because patterns never ran on the seeding path: in cluster mode it collects a `HashSet` into a `Vec`, shuffles it with the seeded RNG, and truncates, so the surviving cell set differs between processes. The other four generators collect a `HashSet` into a `Vec` too, but only the order varies, and setting a barrier is idempotent, so their worlds are identical across processes. The moment terrain runs at seeding, the `Noise` cluster case becomes a cross-process reproducibility defect and `crates/v3-core/tests/reproducibility.rs` must cover a terrain-bearing config.
- `experiments/suites/*.json` (added 2026-03-12) already expresses this recipe shape: a `startup_patch` over defaults plus `default_patterns` entries of `{params, bounds, seed}`. Nothing in the repository consumes it. The proposal supersedes it rather than adding a second format.
- The sweep profile builds its config from `SimulationConfig::default()` plus width, height, founders, and an optional coverage override; the report's `deterministic.profile` block records those five fields and nothing about the world's shape. A baseline reading needs a recipe path and digest in that block.
- Persistence below the default world size is seed-dependent (T01.F11, T11.F04 sweeps: 128² dies on every seed, 256² and 512² are seed-dependent). Any recipe that removes passable area must be checked for persistence at production defaults, exactly as the T04 notes already require for habitat patches.

## 4. Which pressures, and the evidence

Petri's food is already limited (depleted by eating and occupancy, regrown by fertility) and can be typed and regionalized by per-type fertility layers, though the types do not yet differ in payoff, so the resource-competition and spatial-heterogeneity results below are the closest evidence for which worlds to build first. The organisms in every study below are sessile and asexual; Petri's move and see, so patch isolation depends on barriers and corridors rather than on dispersal alone.

**Limited resources are the diversity lever; unlimited ones collapse to one genotype.** Cooper and Ofria (Artificial Life VIII, 2002; read in full) evolved 69 Avida populations of 2,500 with nine resources, 30 with depletable resources and 39 with infinite ones, for 100,000 updates and then 50,000 more with mutation off. Genotypic and phenotypic diversity were significantly higher under limitation (Mann-Whitney, P far below 0.0001), stayed high through the mutation-free phase, and fell to near zero with infinite resources; restarting limited-resource ecosystems with infinite resources collapsed each to the single fittest genotype. The resources were global, and the authors state that coexistence needed no spatial or temporal heterogeneity. Chow, Wilke, Ofria, Lenski, and Adami (Science 305:84–86, 2004; abstract only, the full text is closed and the Caltech deposit holds only the supplement) report the same mechanism at scale: species richness peaked at intermediate resource inflow in a spatially homogeneous world through frequency-dependent selection, and "A diverse pool of limiting resources is sufficient to cause adaptive radiation". For Petri, coverage, growth rate, and fertility bounds are knobs today; the food-type count is not yet a pressure, because a type-specific payoff does not exist until T03.F04 (digestion specialization) or a successor adds one, and the two-food recipe waits for it.

**Where each resource grows matters, and overlap matters more than diversity for complex traits.** Dolson, Pérez, Olson, and Ofria (bioRxiv 148973, 2017; read in full) placed circular patches of nine limited resources on 59-by-59 and 115-by-115 Avida grids, 30 replicates per treatment, 100,000 updates. Phenotypic Shannon diversity rose with environmental entropy across 500 random layouts (slope 0.32, standard error 0.02, R² 0.28) and peaked where environmental entropy peaked in the fixed-layout experiments (patch radius about 13 to 23; inter-patch distance about 14 to 21). A two-resource niche needed at least about 50 cells of overlap to stay occupied more than half the time. The odds of evolving the most complex function rose 4.3-fold per unit of phenotypic diversity but 148.8-fold per additional resource type per cell, so patch overlap, not heterogeneity alone, drove evolutionary potential. The authors caution that motility or evolved dispersal could change the result. For Petri this says that when a two-food recipe becomes possible its type regions should partly overlap rather than tile disjointly, and it warns that a region must be large enough to hold a population.

**Many smaller connected patches maintain and generate more diversity than one large one, once evolution is on.** Dolson, Wiser, and Ofria (ALIFE 2016, bioRxiv 043083; read in full) took ten populations pre-evolved in the Chow limited-resource environment, then protected 900 of 3,600 cells in square reserves tiled from 900 one-cell reserves to one 30-by-30 reserve, killing 100 to 500 unprotected cells per update, with offspring placed near parents, ten replicates per cell of a full factorial. With mutation on, each unit of log reserve count added about 0.096 to the log of final phenotype count; larger reserves lost more phenotypes (partial eta squared 0.30) and produced fewer new ones (0.065). With mutation off the configuration barely mattered. Reserve size and connectivity were confounded by design, and the authors list corridors and reserve spacing as open questions. For Petri this is the archipelago archetype and the T04.F03 connectivity knob, subject to the persistence floor: Petri's small worlds die, so islands must stay above the passable area that persists.

**Borders between resource combinations are where new traits tend to appear.** Dolson and Ofria (ECAL 2017, bioRxiv 149302; read in full) ran 100 replicates in each of eight random patch environments and a homogeneous control on a 60-by-60 grid and located where each of nine traits first evolved. Forty-three of 81 trait-by-environment point patterns were non-random and 40 had hotspots; the homogeneous control had none. Local diversity did not predict hotspot location for the five most complex traits, and resource presence explained little across environments; hotspots often sat on borders between resource combinations. For Petri this supports composite worlds inside the baseline set, and gradients and borders rather than uniform regions inside a recipe.

**Rich and rare against poor and abundant: foraging theory names the switch.** MacArthur and Pianka (American Naturalist 100:603–609, 1966; read in full) rank food items by harvest per unit time and enlarge the diet while the fall in search time per item exceeds the rise in pursuit time; the optimal diet narrows where food is dense, because search is cheap, and broadens where it is sparse; an item worth eating without competition stays worth eating after competition arrives; larger patches are used more selectively than small ones, because travel between patches grows with their linear size while hunting area grows with its square; and specialists coexist against a jack-of-all-trades only when the generalist's lower efficiency outweighs its travel saving. Charnov (Theoretical Population Biology 9:129–136, 1976; read in full) adds the marginal value theorem for a forager that depresses its own patch: leave when the intake rate there falls to the habitat's average, supported by chickadee experiments in which the giving-up time was constant across patch types within an environment and shorter where food was rich. For Petri, where search is movement and decay per tick and handling is the one-tick eat action, this fixes the design of the food landscape and the orchard recipe: energy per bite, coverage, and regrowth per type are the three knobs the theory uses; the pressure to prefer the rich food turns on the rich food's own density, so recipes should sit on both sides of that switch; a slow recovery rate is what makes remembering when a patch was last grazed pay, the pressure T02.F04 later deepens; and specialist coexistence needs a cost for breadth that only a body-side feature such as T03.F04 supplies, so the world-side landscape alone selects on where to go and what to eat.

**Already reviewed by the program and not repeated here**: the fluctuating-environment and static-world evolvability papers cited in the T02 notes, and the digital-evolution ecology review cited in T04.

## 5. How other platforms express a world

- **Avida** (`environment.cfg`, project wiki): `RESOURCE`, `GRADIENT_RESOURCE`, and `CELL` keywords; a spatial resource carries `geometry` (`global`, `grid`, `torus`), `initial`, `inflow` and `outflow` with rectangles (`inflowx1`, `inflowx2`, `inflowy1`, `inflowy2`, and the outflow box), `xdiffuse`, `ydiffuse`, `xgravity`, `ygravity`. Regions come from inflow and outflow boxes; per-cell overrides come from `CELL` lines; the seed lives in `avida.cfg`, not in the environment file.
- **Polyworld** (SourceForge project news, 2006-06-22): one worldfile drives a run; food is placed by `FoodPatch` objects, any number of rectangular or elliptical patches with their own amounts and growth rates, distributed uniformly, linearly, or normally, probabilistically or deterministically.
- **Neural MMO** (project documentation, summary only): the default map generator is multi-octave Perlin noise seeded by Perlin noise, replaceable through a `MAP_GENERATOR` config argument.

All three regenerate the world from parameters and a seed rather than storing the map, and Avida's `CELL` lines are the same hand-authored escape hatch the bitmap layer would be.

## 6. Recommendation

Create track **T12 — World Composition and Baseline Worlds** (drafted with four features; the food-landscape feature was merged into the baseline set later on 2026-09-08, leaving three plus the unscheduled T12.F05), and re-point the three rows that currently assume T02.F02 generates terrain. The draft track is at [`docs/roadmaps/t12-world-composition-and-baseline-worlds.md`](../roadmaps/t12-world-composition-and-baseline-worlds.md); the amendments are in the master roadmap and the T02, T04, and T06 tracks, all uncommitted for review.

1. **T12.F01 — Seeded Terrain in the World Config.** `world.terrain` as an ordered list of layers, each an existing `PatternParams` with optional bounds (default whole world) and optional seed, applied in `seed_simulation` after the world is created and before fertility, food, and founders; `world.world_seed` as an optional fixed seed for terrain and fertility; the `Noise` cluster hash-order fix; the named generator behind the world-generation path, verified bit-identical; the reproducibility test extended with a terrain-bearing config; the server startup schema, frontend `types/config.ts`, a Terrain section beside World Topology in the startup panel, and the `v3-world-grid-spec.md` Section 4 rows and the `v3-startup-seeding-spec.md` Section 4 flow step all in the same feature, because `deny_unknown_fields` rejects a field the schema does not know. Production default: empty terrain, so gate and goal trajectories do not move.
2. **T12.F02 — World Recipe Save and Load.** The CLI accepts a partial config merged over defaults; the frontend saves the effective config from `GET /v3/simulation/config` and loads a recipe file into the startup request; `run_started` carries the config digest; `bench --profile sweep` accepts `--config`, and the report's profile block records the recipe path and digest. `experiments/` is retired. No new format, no version field.
3. **Food landscape (drafted as T12.F03; merged into T12.F04 on 2026-09-08).** Per-type energy per unit, regrowth rate, and recovery rate on `FoodTypeConfig`, each optional and defaulting to the shared value, applied in the typed eat path and the per-type growth pass; viability first; the one-food production default and its trajectory unchanged; new rows in `v3-world-grid-spec.md` Section 4 and the eat reward rule in `v3-runtime-config-spec.md`; the frontend food-type card gains the fields. Not a nutrient budget.
4. **T12.F04 — Baseline World Set.** The food landscape above plus the four fixed recipes (plains, orchards in grassland, canyon country, and the composite) under a `worlds/` directory with a README of the exact `make bench` invocation per recipe, the `FbmThreshold` terrain variant, the persistence and connectivity readings stored under `docs/progress/sweeps/t12-f04/`, and the reading protocol written into the track notes. Composites are in the set from the start (user decision 2026-09-08); the set is composed only from tick-zero properties, and the T02 dynamics are read against it rather than included in it.

Amendments: T02.F02 becomes "Occlusion, Creature Opacity, and Sensory Noise" and depends on T12.F01 as well as T02.F01; T04.F03 names T12.F01's terrain and gains it as a dependency; T06.F01 depends on T12.F01 instead of T02.F02, since it needs seeded barriers rather than occlusion. T09.F08's dependency on T02.F02 is unchanged.

Priority: T12.F01 and T12.F02 are inserted directly after T11.F18, which the user made the next new start later on 2026-09-08, because the user named this as a next track and because none changes a production trajectory, so they cannot confound the T11 readings. T12.F04 is placed immediately before T02.F01, after T11.F13: its stored readings are the baseline the environmental features are compared against, and a baseline taken before the T11 supply repairs would make T02.F01's delta span those repairs, the attribution problem that already placed T02.F01 after T11.F13. The alternative is a paired reading of the set on `main` at the start of each environmental feature, about 45 minutes each.

## 7. Decisions for the user

1. **Ownership.** Approve the new track and the T02.F02 re-scope, or keep terrain generation inside T02.F02 and have T12 depend on it (the rejected row in Section 3.4).
2. **World-seed semantics.** `world.world_seed` absent derives terrain and fertility from the run seed (today's behavior, so seeds 11/22/33 remain three maps); present, it fixes the map while food seeding, founders, and the run RNG still vary by seed. The alternative is to always fix the map per recipe, which makes every baseline one map and loses map variance in the readings.
3. **Painted worlds.** Whether hand-painted terrain must be saveable now (adds the `Bitmap` layer to T12.F01) or later.
4. **Placement.** Whether T12.F01 and T12.F02 follow T11.F18 as drafted, and whether T12.F04 waits for T11.F13 as drafted or is pulled forward with paired readings at each consumer.
5. **Add or replace.** The request was for baselines to replace the current testing seeds. This note recommends adding the set beside the goal profile, with the default world doubling as the plains baseline, for two reasons: the master criteria compare every goal reading against the goal series' first row, so a new world starts a new series and breaks the T11 comparison; and the set costs about 45 minutes per reading, which the per-closure budget the user cut twice cannot absorb for every feature. Replacing is possible if those two costs are accepted; the call is the user's.
6. **Food knobs.** Which per-type fields the food landscape exposes. Recommended: energy per bite, regrowth rate, and recovery rate, with placement already covered by `SingleType` fertility layers and coverage by the existing per-type field; no per-type handling cost until a body-side digestion feature exists, because handling in the theory is a property of forager and food together.

## 9. Remaining uncertainty

- Whether `rand_xoshiro` 0.6.0's `Xoshiro256PlusPlus` reproduces `SmallRng`'s stream bit for bit at every seed is expected from the two sources but not yet executed; T12.F01's first test settles it, and the fallback is recorded in Section 3.3.
- Whether the archipelago and labyrinth recipes persist at 1600² with production founders is unknown until T12.F04 runs them; the T01.F11 and T11.F04 sweeps say passable area below roughly the 512² scale is seed-dependent, so island and corridor sizes start large.
- Whether evolution can reach a food preference on the current substrate is untested: the eat action's type index is decoded from an evolvable action parameter and per-type food sensors exist, so the path is open, but nothing has measured how often a mutation changes the eaten type. T12.F04's spec reads that on the founder neighborhood. Specialist coexistence, as distinct from a preference, needs T03.F04's cost for breadth.
- Chow et al. 2004 was read at abstract depth only.
