# T11 — Brain Genotype-Phenotype Map

**Status**: In Progress
**Last updated**: 2026-09-05
**Master**: [Program Roadmap](../roadmap.md)

## Goal

Petri's brain is a heterogeneous mesh: nodes of any compute kind that read
sensors, shared memory, and an upstream bus, steer which node runs next, may
write memory as a side effect, and commit one action or a queue each tick.
Make the map from that genome to behavior evolvable: a brain can gain an
instruction, a node, an edge, or a memory motif and usually still act as its
parent did, so lineages accumulate structure through neutral and near-neutral
steps, and remembered state advances on a clock the world sets. Write the
properties that make this true as the contract every node kind must meet,
repair the existing VM and graph kinds against it first, and change a
representation only where the neighborhood reading still shows a gap.

## Track Success Criteria

- [ ] A mutational-neighborhood indicator reports the silent, changed, and dead fractions per operator and per birth on single-tick and short multi-tick batteries: the founder half inside the gate profile at every closure program-wide, the evolved-genome half in the goal profile.
- [ ] Structural VM edits (insert, delete, replace, motif insertion, block and slice copies) preserve every surviving control-flow reference outside the edited span, verified by property tests, and no single operand-level VM event redraws more than one field (opcode replacement stays a separate macro operator).
- [ ] Adding or copying a graph compute node, or adding an input reference, is silent on the founder battery at least 95% of the time, and new edges can reach every sensor sub-value.
- [ ] At production defaults, mutated births are behaviorally dead at most 5% of the time and single-event births are silent at least 60% of the time, with every behavior-changing operator family still enabled.
- [ ] Persistent graph state and eligibility traces advance on an explicit world-tick clock, verified by fixtures across relaxation-pass limits, disconnected-node additions, and skipped module visits.
- [ ] Copying a working module keeps it working, and learned weights follow surviving homologous nodes and edges through structural mutation.
- [ ] Founders reach and retain a useful remembered decision through viable mutations in a bounded delayed-cue task.
- [ ] The node-type contract (references stable by id or remapped on every edit, growth that preserves function when it fires, persistent state that advances once per world tick, mutation delivered in small steps) is recorded in the reference specs, and every backend, existing or added, is checked against it by property tests and the neighborhood indicator.
- [ ] Every floor above is met by the close of T11.F10, and from T11.F01 onward no closed feature anywhere in the program lowers an indicator component below the previous closed feature's reading unless its spec predeclared and justified the change.

## Executable Features

- [x] **T11.F01 — Mutational Neighborhood Indicator** — Depends on: T01.F12
  - Goal: One step away. At every closure, read how often a single mutation leaves a brain acting like its parent, acting differently, or not acting at all, on the founder and on evolved genomes, with floors predeclared before any repair; observation only.
- [x] **T11.F02 — VM Structural Mutation Semantics** — Depends on: T11.F01
  - Goal: Gene insertion, deletion, and duplication. Adding, removing, replacing, or copying instructions keeps every surviving jump pointing where it did, an operand mutation changes one field by a small step, terminals stay terminals, and a register count never aliases registers.
- [ ] **T11.F03 — Function-Preserving Graph Growth** — Depends on: T11.F01
  - Goal: New neural connections. A compute node joins the circuit disconnected or by splitting an existing edge with its function preserved, copies never rewire live nodes, and new edges can reach every sensor sub-value.
- [ ] **T11.F04 — Mutation Supply and Neutral Scaffold** — Depends on: T11.F02, T11.F03
  - Goal: Point mutations one at a time. The same expected mutation supply arrives as mostly single events instead of ten-event bursts, mutation lands on inactive structure as readily as on live code, and persistence is re-read after the change.
- [x] **T11.F05 — Temporal Controller Fixtures** — Depends on: None
  - Goal: Check the brain's building blocks with small delayed-cue, memory-retention, and delayed-reward fixtures on constructed controllers, recording capability and measured gaps before interpreting evolution.
- [ ] **T11.F06 — Graph Memory Clock** — Depends on: T11.F01, T11.F05
  - Goal: Neural timescales. Remembered graph state, including what a backward edge reads, advances once per world tick, so extra settling passes or disconnected computation cannot speed up forgetting.
- [ ] **T11.F07 — Reward Trace Clock** — Depends on: T11.F05
  - Goal: Synaptic eligibility. Recent activity fades with elapsed world time and influences later learning through one explicit, calibrated reward-update rule.
- [ ] **T11.F08 — Function-Preserving Duplication and Module Growth** — Depends on: T11.F02, T11.F03, T11.F06
  - Goal: Gene duplication. Copying a working module keeps it working, so complexity can grow by copy and divergence as in real genomes.
- [ ] **T11.F09 — Learned-State Inheritance Integrity** — Depends on: T11.F07, T11.F08
  - Goal: Inherited neural adaptation. When learned weights are heritable, structural mutation preserves their association with surviving connections and initializes new connections explicitly.
- [ ] **T11.F10 — Memory-Motif Evolvability from Founders** — Depends on: T11.F04, T11.F09
  - Goal: Can memory be found? In small temporal tasks, measure whether founders reach and retain useful remembered decisions through viable mutations before testing seasonal ecology.
- [ ] **T11.F11 — Label-Addressed Control Flow** — Depends on: T11.F02, T11.F08
  - Goal: Conditional on the T11.F01 reading after T11.F02 and T11.F08. Promoter sequences, not positions: a jump finds its target by an evolvable label with nearest-match resolution, so duplicated or shifted code keeps working without per-operator reference repair.
- [ ] **T11.F12 — Neutral Network and Robustness Characterization** — Depends on: T11.F01, T08.F02
  - Goal: Slack in the genome. How much neutral structure absorbs mutation and keeps function intact, distinguished from unreachable bloat.

At production defaults on the V3Alpha1 founder at commit 4b8650ef, 90.2% of births are clones; of mutated births, 5.9% are silent on a 48-scenario reactive battery, 75.4% changed, and 18.7% dead (NoOp on every scenario); single-event births are 32.4% silent and 4.1% dead; memory-motif inserts are 13 to 24% silent; `AddInternalGraphNode` is 1.0% silent and adds 29.5 edges per event; inserting one `Noop` is 28.8% silent today and 100% silent once the jumps that straddle it are recomputed. Cite the audit rather than re-deriving these numbers; re-run its probes (appendices of the document) when a later commit needs fresh ones. T01.F12's goal-v1 baseline (read 2026-09-04, verified 2026-09-05) corroborates the audit on evolved populations: zero of 24,418 final creatures across three seeds changed their action queue when shared memory was zeroed or rotated, while reachable structure grew to a median of 97, a p75 of 124, and a maximum of 798 against the founder's 96.
- Ownership. T11 owns the brain's representation (VM ISA, graph encoding, mesh routing as a genome), the execution semantics that make the phenotype stable in time (graph state and trace clocks), the variation operators and the per-birth mutation supply, the learned-state inheritance rules, and the neighborhood indicator. T08 owns lineage attribution, heritable mutation policy, mating, and recombination. T09 owns cognition assays, learning qualification, and the diagnostic checkpoint. Features moved here on 2026-09-04 keep their scope: T11.F01 was T08.F01, T11.F02 was T08.F10, T11.F03 was T08.F11, T11.F05 was T09.F09, T11.F06 was T09.F10, T11.F07 was T09.F11, T11.F08 was T08.F04, T11.F09 was T08.F12, T11.F10 was T09.F02, and T11.F12 was T08.F03; T11.F04 and T11.F11 are new. Retired IDs are never reused.
- Node-type contract. The mesh cannot inherit evolvability from any one representation the way NEAT, Markov brains, or SignalGP do inside theirs, so it must guarantee four properties in its own contract, and the audit is the record that they were never written down: (1) every internal reference is stable by id or remapped on every edit (T11.F02 for VM jumps; T11.F03 and T11.F08 for graph indices and copies; T11.F11 if labels are adopted); (2) every growth operator preserves function at the moment it fires (T11.F03, T11.F08); (3) every piece of persistent state advances once per world tick (T11.F06, T11.F07); (4) mutation supply arrives as small steps (T11.F02 operand steps, T11.F04). Record the contract as a section of `docs/reference/v3-mutation-spec.md` with pointers from the VM and graph backend specs when T11.F02 lands, and extend it as later features refine it. A new node kind (a gate bank in the Markov-brain style, a further network flavor) is welcome as a bounded T11 feature that meets the contract and the floors and carries its applied energy cost; it needs no measured gap, only the contract. Replacing the mesh itself, or fan-out that runs several nodes per tick under a hop budget, does need a measured gap: keep the single-successor chain, since nothing in the audit shows the chain blocks cognition, and shared memory already serves as the side channel between nodes. T11.F06's clock decision is what makes the graph node a true recurrent-network flavor. The reconciliation with the original mesh vision is in the companion document.
- Floors and the no-regression rule. The floors below were predeclared on 2026-09-04 from the audit's founder battery. The T11.F01 spec fixes their final values from the fuller battery (multi-tick sequences, evolved genomes) before any repair lands, and may set a value below the audit's only with a recorded reason; after T11.F01 closes no floor is loosened. Floors are track-level: they are met by the close of T11.F10, not by each repair, because the dead and single-event floors cannot be reached before the supply change in T11.F04. The per-feature rule is no regression, mirroring the compute-regression rule: the founder half of the indicator runs in the gate profile for every closed feature program-wide, since any feature can change mutation or runtime semantics, and no closed feature lowers an indicator component below the previous closed feature's reading unless its spec predeclared and justified the change. Each T11 repair feature names, before implementation, the components it expects to move and in which direction. Floors: (a) inserting one `Noop` with jump repair, or copying a block into an unreachable span, leaves the battery trace identical for any program whose jumps target in-range instructions and whose execution stays under the step cap (property tests); (b) memory-motif insertions are at least 80% silent on the founder; (c) graph add-node and copy-node and input-reference addition are at least 95% silent; (d) mutated births at production defaults are at most 5% dead; (e) single-event births are at least 60% silent. Floors are minimums that say structural growth is usually neutral; they are not a score, and no feature may meet one by disabling or down-weighting a behavior-changing operator family. Every T11 feature that changes simulation semantics re-reads the indicator and runs `cargo test -p v3-core --test viability` before closure, and reports any persistence shift against the T01.F11 baseline rather than hiding it.
- Sequencing. T01.F12 closed first (2026-09-05) so the goal-profile series has an unrepaired baseline, and each T11 closure's effect on lineage diversity and memory sensitivity is attributable to it. After that, the master execution order runs T11 in ID order through T11.F10; T11.F11 is conditional and T11.F12 is unscheduled. T02.F01 follows T11.F10. Repairs do not wait for long diagnostics: the indicator is the acceptance test for each repair and takes seconds. T11.F05 has no dependencies and changes no production behavior, so a concurrent session may take it while T01.F12 or an earlier T11 feature is in progress.
- T11.F01 runs in process on the founder and on genomes sampled from a predeclared seeded run, adding the T11.F05 temporal motifs once they exist. It reports silent, changed, and dead fractions per operator at one event and per birth through the production engine bucketed by applied event count, on fixed sensor batteries that include single-tick snapshots and short multi-tick sequences with persistent memory and graph state, so the classes stay meaningful once T11.F06 lets state cross ticks; paired short world trajectories for survival and reproduction are optional and not required for closure. A snapshot action match is not viability, and an operator-labeled semantic-change counter is not behavioral novelty. Predeclare samples, seeds, batteries, trajectory lengths, and compute limits. The founder half runs inside the gate profile in seconds; the evolved-genome half runs in the goal profile, bounded to a predeclared sample of tens of genomes with reduced trials so it fits the goal profile's ten-to-fifteen-minute budget (the founder probe alone took 130 seconds per genome in a debug build). Alongside the fractions, report structural companions per sampled genome: whether any reachable instruction or edge reads or writes shared memory, and whether any stateful compute node or plasticity is present, so a zero sensitivity reading is attributed to absent structure, inert structure, or a probe blind spot rather than read as one thing. The T01.F12 memory-sensitivity probe perturbs current shared memory only, not previous-tick slots or persistent graph state. Include raw operand redraws versus single-field perturbations and burst versus single-event supply as diagnostic treatments. Do not change production probabilities in this measurement feature. The audit's two probe tests are the draft; lift them into a maintained test and a bench indicator rather than rewriting them. Indicator readings live in the report's `deterministic` block and must reproduce byte-for-byte across two runs; new report fields follow the T01.F11 precedent of serde defaults so stored reports still load.
- T11.F02 owns VM insertion, deletion, replacement, memory-motif insertion, and block and slice copying in `crates/v3-core/src/mutation/vm/operators.rs` and the jump semantics in `runtime/vm.rs`. Today no splice recomputes the offsets of jumps that straddle it; the remapped block copy adds the positional delta to every jump in the block (internal targets should keep their offset and external ones need the opposite sign); raw-field mutation redraws every operand of an instruction and turns a jump offset into a random i32; terminal and no-op instructions are rewritten into random pushes; and a register-count decrement aliases the top register onto register 0 through the modulo resolution. Its spec defines internal, external, deleted, and wrapped-target policies for every splice (a jump whose provisional target is out of range wraps by program length at runtime, so the remap computes the absolute target under the old length and re-encodes it under the new one), single-field operand steps with a bounded jump nudge, register growth or remapping instead of aliasing, and register slack in the founder, with property tests for surviving references and the T11.F01 battery for behavior. Preserving references does not require every mutation to preserve behavior.
- T11.F03 replaces the current `add_compute_node` in `crates/v3-core/src/mutation/graph/operators.rs`, which adds one random-weight edge per sub-value of every input reference to random surfaces including the action and execute gates. Growth options are a disconnected node, a node with one bootstrap edge, and a NEAT-style split of an existing edge whose incoming weight is 1 and outgoing weight is the old weight. `copy_compute_node` stops adding a backlink into a live node, and new edges sample sub-indices through `mutation/compound.rs` instead of fixing them at 0. The feature also fixes the operator taxonomy the contract relies on: growth operators (add compute node, copy compute node, copy subgraph, add input reference, mesh add, splice, and copies) must be neutral at the moment they fire, so the input-reference `Add` operator, which today wires the new reference into a random surface, leaves it unwired or wires it only into a disconnected node; connection and parameter operators (add, retarget, or remove edge, copy edge bundle, swap kind, mutate parameter, input-reference swap and raw field) may change behavior and must do so in one small step. Measure retained behavior and subsequent activation; a permanently disconnected node is the expected neutral first step, not success by itself. Do not import NEAT's speciation or global fitness sharing into ecological selection; spatial population structure is Petri's protection of new structure, and whether it suffices is what the indicator and T11.F10 measure.
- T11.F04 changes production mutation settings, which no earlier T11 feature may do. Deliver the current expected supply (about 0.55 events per birth) as mostly single events, for example a higher trigger probability with a geometric event count; and lower the reachability bias toward the regime in which mutation lands on inactive structure. Re-run the T01.F11 sweep grid, record the new persistence numbers in the spec and the master baseline note, and pass the viability suite at the new settings. Avida's operating point is the reference: a per-instruction copy mutation rate of 0.0075 by default (0.0025 in most published work) plus a 5% chance of one insertion or deletion per gestation, so a 100-instruction ancestor sees on the order of one small edit per offspring. Production mutation and runtime defaults are owned by `docs/reference/v3-runtime-config-spec.md`; new config fields carry serde defaults and normalization there, and cross-process reproducibility (T10.F11) must hold at the new settings.
- T11.F05 (was T09.F09) is engineering characterization, separate from the deferred T09.F01 proof suite. Use existing in-process runtime and test seams and small constructed reactive, shared-memory, stateful-graph, and plasticity cases; include delayed cues with identical current observations, several delay lengths, disconnected-node perturbations, and rewards after skipped module visits. Record expected and observed behavior under production settings. It may close with explicitly recorded capability gaps assigned to T11.F06 and T11.F07, but never by waiving a failing required check or calling a gap a pass. It changes no production behavior. T09.F08 and T09.F01 reuse its fixtures.
- T11.F06 (was T09.F10) separates persistent temporal updates from within-tick graph relaxation. Current `runtime/cgp/execute.rs` zeroes every compute output at the start of each dispatch and advances stateful operators on every relaxation pass, including passes prolonged by disconnected nodes, so a backward edge reads the previous pass rather than the previous tick and a `DecayIntegrator`'s timescale depends on unrelated structure. Its spec decides between persisting converged outputs across ticks and replacing relaxation with one synchronous update per tick in which backward and self edges read last tick's outputs, as NEAT activation and Markov brains do; the second makes every recurrent edge a one-tick memory element, gives the explicit clock this feature exists for, and cuts per-tick graph cost from at least three passes to one. Define state visibility, repeated dispatch within a tick, and energy-exhaustion rollback; verify memory trajectories across pass limits and disconnected-node additions while preserving combinational computation; audit realized energy and compute costs separately. Changing pass semantics changes per-tick graph cost and the meaning of the `graph_relax_iters` work counter, so the spec predeclares the expected compute change and records the counter's new definition in the benchmark series rather than comparing across it silently. The goal profile's memory-sensitivity indicator perturbs current shared memory only; when graph outputs persist across ticks, this feature adds a versioned indicator component that perturbs persisted graph state and previous-tick slots, coordinated with the intervention set T09.F08 defines, so memory that moves into graph state does not vanish from the reading. This feature does not replace the VM or add a new controller family.
- T11.F07 (was T09.F11) defines the time unit and gain of eligibility traces and reward updates. Current `runtime/plasticity/traces.rs` decays only on module execution while `simulation/tick.rs` applies rewards each tick, and the learning rate enters both the trace and `runtime/plasticity/reward.rs`. Test skipped and repeated visits, immediate and delayed rewards, exact one-edge updates, and a small live-versus-frozen reversal task. Remove stale-credit timing and explicitly justify the gain rule rather than assuming the double application was accidental. T09.F03 later measures ecological usefulness.
- T11.F08 (was T08.F04) uses the T11.F01 neighborhood and the corrected VM and graph semantics to qualify the existing copy operators: preserve internal references, account for shared-memory and output interference, and demonstrate copy-and-divergence on short trajectories. Separate functional preservation from applied energy cost; structural disconnection alone does not establish neutrality. For the VM, neutral duplication places the copy in an unreachable span (after the last terminal, subject to the T11.F02 wrapped-target policy) so it becomes reachable only by a later jump; copying inline into live code is an ordinary macro mutation and is measured as such, and label addressing (T11.F11) is the durable route to duplicated modules that are callable rather than inlined.
- T11.F09 (was T08.F12) owns learned-weight correspondence through node and edge insertion, deletion, and copying in `simulation/actions/reproduction.rs` and `cgp_reproduction.rs`. Define which homologous weights survive and which reset; positional array indices alone are not homology. Cover ordinary and Lamarckian offspring without enabling new inheritance modes or changing the established reset of eligibility traces.
- T11.F10 (was T09.F02) uses the corrected substrate and supply on bounded delayed-cue or alternation tasks where current observations alone cannot determine the correct response. First demonstrate a constructed memory controller's advantage over a matched reactive control. Then measure discovery from founders, viable intermediate changes, retention, and outcomes across predeclared seeds, births, mutation opportunities, and wall-clock limits. Hold observation and action access fixed and separate execution changes from mutation treatments. Hand-built success proves capability, not emergence; failure to evolve within budget is an accessibility result for that exposure, not proof of impossibility. Authored tasks are diagnostics, off in production.
- T11.F11 is conditional. Plan it only if, after T11.F02 and T11.F08 close, the indicator still shows VM insert-class operators below floor (b) or VM duplication failing floor (a), or if keeping the reference-remap invariant across operators proves error-prone. It extends the ISA rather than replacing it: labels are instructions carrying an evolvable tag, jumps carry a tag resolved to the nearest matching label (exact, then closest, then fall through), a one-instruction skip branch may be added, and shared-memory slots stay immediate-addressed. Behavior changes for all genomes, which this repository allows.
- T11.F12 (was T08.F03) characterizes neutral structure along the lineages T08.F02 attributes; it is unscheduled until T08.F02 is.
- Replacing the mesh or a controller family is a new bounded T11 feature justified by a measured gap in the indicator, with matched observations, actions, task exposure, and compute accounting; none is planned. New node kinds follow the node-type contract bullet above instead.
- Every T11 repair is a behavior change under `AGENTS.md`: write the failing fixture or property test first, commit any `proptest-regressions/` files, run `cargo test -p v3-core --test viability` first when defaults or tick mechanics change, and load the relevant `$rust-skills` rules. Each feature updates the reference spec that owns the changed semantics in the same feature (`v3-mutation-spec.md`, `v3-vm-isa-spec.md`, `v3-graph-backend-spec.md`, `v3-runtime-config-spec.md`, `v3-reproduction-spec.md`), and the node-type contract section lands with T11.F02. Seeded runs must stay byte-for-byte reproducible across processes after every feature.
- Research basis reviewed 2026-09-04, from primary text unless noted: [Ofria, Adami, and Collier, Design of Evolvable Computer Languages, IEEE TEC 2002](https://langev.com/pdf/ofria02ieee.pdf) (differences in evolvability between five instruction sets were attributable mainly to mutational robustness; the set that replaced nop templates with an explicit jump distance was the least evolvable); [Brameier and Banzhaf, Linear Genetic Programming, 2007](https://link.springer.com/book/10.1007/978-0-387-31030-5) (a false branch skips exactly one instruction; introns protect effective code and allow neutral variation; variation step size of one instruction); [Miller and Smith, IEEE TEC 2006](https://pure.york.ac.uk/portal/en/publications/redundancy-and-computational-efficiency-in-cartesian-genetic-prog) (the most evolvable CGP genotypes have over 95% inactive genes; abstract); [Goldman and Punch, IEEE TEC 2015](https://dl.acm.org/doi/abs/10.1109/TEVC.2014.2324539) (single active mutation and skipping neutral evaluations; abstract); [Stanley and Miikkulainen, NEAT, Evolutionary Computation 2002](https://nn.cs.utexas.edu/downloads/papers/stanley.ec02.pdf) (add-node splits an edge with incoming weight 1 and the old outgoing weight); [Hintze et al., Markov Brains, 2017](https://arxiv.org/abs/1709.05601) (start-codon genes in a mostly non-coding genome; insertion, deletion, and duplication of hundreds of sites are routine); [Lalejini and Ofria, SignalGP, GECCO 2018](https://arxiv.org/abs/1804.05445) and [Lalejini, Moreno, and Ofria, GPEM 2021](https://link.springer.com/article/10.1007/s10710-021-09406-8) (tag-based references with inexact matching; module regulation helped context-dependent tasks and could hinder others); [Wilke et al., Nature 2001](https://www.nature.com/articles/35085569) (at high mutation rates selection favors mutational robustness over replication rate); [Wagner, Proc. R. Soc. B 2008](https://royalsocietypublishing.org/doi/10.1098/rspb.2007.1137) (phenotype robustness promotes evolvability); [Clune et al., PLoS Comput. Biol. 2008](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1000187) (evolved mutation rates land far below the long-term optimum); [Avida mutation settings](https://github.com/devosoft/avida/wiki/Mutation-settings) and [instruction set](https://github.com/devosoft/avida/wiki/Instruction-Set). Carried from the earlier T08 and T09 reviews: [The evolutionary origin of complex features](https://doi.org/10.1038/nature01568), [recurrent Cartesian genetic programming](https://doi.org/10.1007/s10710-016-9276-6), and [The Evolutionary Origin of Associative Learning](https://doi.org/10.1086/706252). Prior art for the heterogeneous mesh itself, reviewed 2026-09-05 (abstracts and secondary summaries unless noted): [Genetic Network Programming, Mabu, Hirasawa, and Hu, Evolutionary Computation 2007](https://direct.mit.edu/evco/article-abstract/15/3/369/1274/A-Graph-Based-Evolutionary-Algorithm-Genetic) (judgment nodes read sensors and choose the next node, processing nodes act, a fixed node pool with evolvable links); [PADO, Teller and Veloso, 1995](https://www.cs.cmu.edu/~mmv/papers/Teller-ESJ.pdf) (each node executes an action then a branch decision over an indexed memory; no natural crossover for such networks); [Sims, Evolving Virtual Creatures, SIGGRAPH 1994](https://www.karlsims.com/evolved-virtual-creatures.html) (a directed graph of heterogeneous node functions including memory and oscillators); Markov brains as above (heterogeneous gate kinds over one state buffer; gate choice shapes the adaptive trajectory); [Koza's architecture-altering operations](https://www.researchgate.net/publication/2655092_Evolution_of_Both_the_Architecture_and_the_Sequence_of_Work-Performing_Steps_of_a_Computer_Program_Using_Genetic_Programming_with_Architecture-Altering_Operations) (subroutine duplication yields an offspring semantically equivalent to its parent); [Atkinson, Plump, and Stepney, Evolving graphs with semantic neutral drift, Natural Computing 2021](https://eprints.whiterose.ac.uk/id/eprint/154735/1/Atkinson2019_Article_EvolvingGraphsWithSemanticNeut.pdf) (semantics-preserving mutations on active structure improve evolutionary performance); [Greve, Jacobsen, and Risi, Evolving Neural Turing Machines, GECCO 2016](https://dl.acm.org/doi/10.1145/2908812.2908930) (an evolved controller with external read-write memory retains information longer than plasticity alone).
