# T14 — Runtime Telemetry and Report Integrity

**Status**: In Progress
**Last updated**: 2026-09-11
**Master**: [Program Roadmap](../roadmap.md)

## Goal

What the simulation applies is what the closure report records. Deaths, energy
flows, carried structure and production mutation are readable from stored
telemetry rather than inferred from work counters, the comparison chain names the
closure it actually compares against, and every indicator under the no-regression
rule is visible to it. Beyond repair, the report reads the north star directly:
whether surviving clades live differently and for how long they coexist, and
whether brains that remember out-reproduce brains that only react. This track is
the microscope: it records applied behavior and adds no mechanism.

## Track Success Criteria

- [ ] Every energy flow the simulation applies — intake, action charges, compute charge, carrying cost, parental transfer — has a stored total on the goal profile, so any cost can be stated as a share of what the population earns rather than as a nominal rate.
- [ ] Creature death is counted and attributed to the sink that caused it, so a feature whose stated mechanism ends in death is verified at its own closure rather than through a work-counter proxy.
- [ ] Every closure report names a comparison reference that is a different, earlier closure, or records the absence of one; no report compares against itself.
- [ ] Every indicator wired into the goal profile appears in the comparison block the no-regression rule reads, and carries a version or definition token that moves when its definition moves.
- [ ] Population readings the report takes once at the horizon — lineage diversity, carried structure, generation depth — are also taken at the persistence checkpoints the run already samples.
- [ ] Counters the runtime already maintains reach the stored report or are deleted; no counter is transferred whose value is structurally constant.
- [ ] Reproductive success and lifespan are stored by cognitive class, so whether memory-carrying brains out-reproduce reactive ones is read from applied outcomes rather than from perturbation alone.
- [ ] Each surviving founder clade has a stored behavioral profile — what it eats, what it does, where it lives, and when it would have gone extinct — so "many coexisting ways of making a living" is readable as differentiation and duration, not only as a count.
- [ ] The living population's sensor usage is stored at the persistence checkpoints, so whether creatures can perceive what a niche or a memory requires is read before either is looked for.
- [ ] The progress page is organized by the questions the success definition asks rather than by data source; its headline tiles are diversity and cognition indicators, not verification artifacts; every indicator is shown across the three baseline worlds side by side against its floor and first reading; a delta on a single run says so; and compute is one section at the end — still one static file in Git reading the stored JSON, with no composite score, no build step and no service.
- [ ] Every reading added here derives from applied simulation behavior, consumes no production RNG, selects no survivors, changes no execution, and preserves byte-for-byte reproducibility across processes and thread counts.

## Executable Features

- [x] **T14.F01 — Closure Comparison and Indicator Coverage Integrity** — Depends on: None
  - Goal: A closure's verdict means what it says: the report compares against an earlier closure or records that it has none, and every wired indicator is visible to the no-regression rule.
- [ ] **T14.F02 — Existing Counter Transfer** — Depends on: T14.F01
  - Goal: Counters the simulation already maintains — production mutation supply and targeting, mutation lifecycle outcomes, predation, failed eats, energy-exhausted dispatches — become readable at closure instead of being discarded each run.
- [ ] **T14.F03 — Applied Mortality and Energy Accounting** — Depends on: T14.F02
  - Goal: Death is counted and attributed to the sink that caused it, and every energy flow the world applies is totalled, so a cost feature's effect is read from what it did rather than from what it charged.
- [ ] **T14.F04 — Population Readings on the Persistence Checkpoints** — Depends on: T14.F02
  - Goal: Lineage diversity, carried structure and generation depth are read at the checkpoints the run already samples, so a closure shows when a change took hold and not only where it ended.
- [ ] **T14.F05 — Cognition Telemetry Resolution** — Depends on: T14.F02
  - Goal: A plasticity update that moves a weight is distinguishable from one that does not, reward-modulated learning is counted separately from Hebbian, a shared-memory write that changes a slot is counted in production, and the memory indicator reports how many creatures could have responded at all.
- [ ] **T14.F06 — Reproductive Success by Cognitive Class** — Depends on: T14.F03
  - Goal: Whether cognition pays is readable: creatures that read memory, hold state or learn are counted at death with their offspring and lifespan beside those that do not, so selection for remembering is read from outcomes rather than inferred from presence.
- [ ] **T14.F07 — Surviving-Clade Behavioral Profile** — Depends on: T14.F02
  - Goal: Each clade that survives to closure shows how it made its living — what it ate, what it did, how large and how old it grew — so a count of survivors becomes a reading of how many of them live differently.
- [ ] **T14.F08 — Sensor Usage Census** — Depends on: T14.F04
  - Goal: What the population can perceive is read at the checkpoints — which world inputs living brains reference, and how many read anything stateful — so a food niche nobody senses or a memory no brain reads is visible as a closed door.
- [ ] **T14.F09 — Clade Persistence Timeline** — Depends on: T14.F04
  - Goal: Coexistence is read as duration: each founder clade's peak and, if it ends, its extinction tick, so a closure shows whether clades are lost in the founding crash or excluded one by one over the run.
- [ ] **T14.F10 — Spatial Occupancy by Clade** — Depends on: T14.F04
  - Goal: Where life is becomes readable on the worlds built to shape it — a coarse grid of population and clade count at each checkpoint — so habitat partitioning shows as a way of coexisting rather than staying invisible.
- [ ] **T14.F11 — Progress Page Information Design** — Depends on: T14.F01
  - Goal: `docs/progress/index.html` reads as answers rather than a spray of charts: it leads with the questions the success definition asks, shows each indicator across the three worlds side by side against its floor and first reading, labels a single-run delta as single-run, and puts compute last — so a reader sees in one screen whether the world is more alive, more diverse and more cognitive than at the last closure.

## Notes for AI Agents

- Evidence is the [telemetry gap audit of 2026-09-10](../strategy/telemetry-gap-audit-2026-09-10.md) and its JSON companion. The audit labels every claim by verification status: survived three adversarial lenses, spot-checked by the orchestrator, or unverified. **An unverified lead is re-verified during feature planning before it enters a spec.** The audit's synthesis and tiering are the orchestrator's, not a verified agent's, because a session limit killed the verifier and synthesis agents mid-run.
- **Ownership.** T14 owns cross-cutting recording: report integrity, the transfer of existing runtime counters into the stored report, and readings whose need spans features or surfaced after the owning feature closed. It owns no mechanism. T03 retains metabolism and the costs themselves — T14 records what those costs did, and does not change a charge, a rate or a default. T04.F01 retains the ancestry graph and ecotype observation; T14 owns only clade count and entropy at the checkpoints the run already samples. T09.F08 retains new temporal interventions and their indicators; T14 owns the exposure denominator for the intervention that already ships. T11 retains the brain genotype-phenotype contract and its neighborhood, mesh and drift batteries; T13 retains module recruitment observation. T01 retains indicator definitions, the goal profile and `docs/progress.md` as artifacts; T14 repairs the integrity of the comparison mechanism that reads them.
- **The standing rule this track encodes.** A measure introduced by a mechanism feature stays with that feature: the master roadmap already requires any feature introducing a diversity or cognition measure to wire its indicator into the goal profile as part of the same feature, and T14 does not relieve it. A T14 row is for the residue — a need that spans several features, or one that surfaced after its owner closed. When a new telemetry need appears and an open feature owns the mechanism it measures, it belongs to that feature, not here.
- **Determinism is a hard constraint, not a preference.** Seeded runs must reproduce byte-for-byte across processes and thread counts at every goal-profile world size, and the simulator is multi-threaded. Prefer integer counters. Accumulate floats only inside the tick's existing deterministic reduction, which documents queue-order summation at `crates/v3-core/src/simulation/tick.rs:541-543`. A `u64` incremented inside the existing Phase 0 loop is order-independent by construction and is the model for this track. Any feature here runs the reproducibility checks before closure.
- **Observation contract**, carried unchanged from T13.F01: additive observation must not consume production RNG, select survivors or change execution; an unobserved field is unmeasured, never zero; new observation is budgeted in its spec against the existing closure limits. No dashboard, database, service, campaign runner or composite score. Measurement features are exempt from the master roadmap's natural-analog rule, so these goal lines name no analog by design.
- **F01 scope.** Three defects in one feature, because every later closure is read through them. (1) A reference path equal to the report's own output path is skipped and the profile records an absent reference rather than a self-comparison — verified at `docs/progress/features/t12-f04-baseline-world-set-goal.json`, whose 32 readings all compare 8818 to 8818. (2) The three `temporal_memory_sensitivity` fractions join the per-case comparison reading list beside `memory_different_from_either_fraction`. (3) `lineage_diversity`, `memory_sensitivity` and `reachable_structure_size_distribution` gain the version or definition token their neighbours already carry. Historical reports are not rewritten; a reading a report did not measure stays "not measured".
- **F02 scope.** Transfer only; measure nothing new. Production mutation counters including the executed/reachable/unreachable/not-applicable target split, which is T11.F17's own delivery instrument; the applied-behavior sums from `mutation_outcome_summary` and `mutation_value_totals_by_operator`; predation counters; failed eats keyed by requested type; dispatches ending in `EnergyExhausted`. **Exclude `final_energy_sum`** — it is structurally always zero and would become a permanent zero column. Resolve `mutation_events_applied_total_semantic_noop` in the same feature: `semantic_category` has no match arm, so the counter is a constant zero and is exposed over the server payload. Delete it or give it a real predicate; do not transfer it as-is.
- **F03 scope.** Death first: one counter plus an attribution to the sink that took the creature to zero, set at the single `Simulation::remove_creature` funnel. Predation already counts its kills at runtime and only needs joining. Then the flow totals — intake by food type, action charges at their realized multiplier-scaled value, compute and priority-bid energy, carrying cost as a size × creature-tick integral, parental transfer. The spec fixes the variant set, the charge sites and the reduction order; the goal line does not. This feature makes T03.F10's lethality claim and T03.F08's carrying cost re-readable at any later closure, which neither can be today.
- **F04 scope.** Reuse the existing 20 persistence checkpoints and the existing accessors. `structure_means` already returns mean genome size, mesh nodes and generation and is already called by `build_tick_sample` on the `v3-cli run` path; `bench.rs` never calls it. Add the clade count and entropy the terminal reading already computes. Keep the trajectory to counts and means — the clade size distribution itself is a T04.F01 concern, not this feature's.
- **F05 scope.** One additional counter for plasticity updates whose written weight differs from its prior value, at both update sites, alongside the existing total rather than replacing it. Separate the reward-modulated pathway from the Hebbian one. Count shared-memory writes whose value differs from the slot's prior value, in production, using the changed-write predicate that already exists; this is the applied-behavior complement to the perturbation reading and answers whether memory is used in the wild at all, not whether it matters. Store the `structural_companions` carrier census beside the existing `memory_sensitivity` block as the exposure denominator, without redefining the shipped fraction or rewriting historical readings. This adds no intervention and makes no cognition claim; a carrier count is exposure, not capability.
- **North-star rows (F06–F10), added 2026-09-11.** The audit's repairs make existing readings trustworthy; these rows add what none of the existing readings measure. The stored indicators measure presence, not payoff: clade count says which identities survived, not whether they live differently; memory sensitivity says behavior changes when memory is scrambled, not whether the memory-using behavior helps. The master success definition names four things no stored reading touches — ways of making a living (differentiation), coexisting (duration), cognition that is selected for rather than merely present, and prediction. F06 reads selection, F07 and F10 read differentiation, F09 reads duration, F08 reads the perceptual prerequisite for all of them. Prediction has no telemetry-level reading until a cycle exists; see the T02.F01 note below. Every row stays raw counts and sums bounded by the number of *surviving* clades or by a coarse fixed grid, never by the 10,000 founders or the cell count; descriptors, strategy counts and overlap measures derived from these rows remain T01.F04 and T01.F06.
- **F06 scope.** At the single `Simulation::remove_creature` funnel F03 already instruments, classify the dying creature with `structural_companions` — reads shared memory, writes shared memory, holds a stateful compute node, has plasticity — which is already computed per creature, RNG-free, and add `offspring_spawned_count` and `age` to per-class `u64` sums with a per-class count. Twelve integers. Store per case in the goal report. This is correlational and confounded by carrying cost; the spec says so, and the reading is telemetry, not proof. It does not test whether selection acts at all — that is T01.F13's shadow model — and a class with more offspring is not a cognition claim.
- **F07 scope.** Add per-creature lifetime counters for eats by food type and actions by type beside the existing `lifetime_action_attempted_count`, `lifetime_blocked_move_count` and `offspring_spawned_count`. At the terminal read, bucket living creatures by founder `lineage_id` and emit one row per surviving clade: size, mean energy, mean age, mean generation, mean genome size, eats by type, actions by type, and predation kills and losses where the counters exist. Bounded by surviving clades (22–142 today). Founder `lineage_id` is clade identity, not ecotype — the T04 note says so — and two clades can converge on one way of living; the row shows what each did, and nothing here names a strategy. The audit refuted "per-lineage behavioral telemetry" because `WorldTracking::observe` sources world totals by design; a terminal per-clade table is a different, bounded artifact and does not change that design. Raw counts only; descriptors are T01.F04.
- **F08 scope.** `cached_live_vm_world_inputs` already lists, per creature, the world inputs its brain references; graph input references are cached beside it. At each persistence checkpoint F04 samples, count living creatures referencing each `WorldInputKey`, and separately count those referencing any stateful source — previous shared memory, persisted node state — so the population's perceptual reach and its temporal reach are both a time series. Pure structure, no execution, near-zero cost. A population that reads only `FoodHere { type 0 }` cannot differentiate on food; one that reads nothing stateful cannot remember. This is exposure, read before capability is looked for.
- **F09 scope.** Keep a live clade count map, `HashMap<lineage_id, u32>`, incremented at birth and decremented at the `remove_creature` funnel; when a clade's count reaches zero, record its extinction tick, and track peak size and peak tick as it goes. Emit per founder clade only those that reached a stated peak or survived, so the table stays bounded. F04 gives the count at 20 checkpoints; this gives the loss curve itself and distinguishes the tick-150 founding crash from ongoing competitive exclusion. T04.F01 retains the ancestry graph; this row records timing, not descent.
- **F10 scope.** A coarse fixed grid — the spec picks a divisor of the world size, on the order of 16 cells per axis — with, per cell and per checkpoint, the population and the number of distinct clades present. No per-creature positions are stored and no full-resolution map. On Orchards, Canyon and Confluence this reads whether clades partition habitat, which is a way of coexisting the current world-total readings cannot see. Keep the cell-to-clade reading to a count; a dominant-clade field is optional and the spec decides.
- **F11 scope, added 2026-09-11.** The page is `docs/progress/index.html`: one static file in Git that reads `benchmark-series.json` and the per-feature JSON, already accepted as the visual companion to `docs/progress.md`. It stays that — no build step, no service, no database, no composite score. What changes is its information design and which metrics earn a place. Read on 2026-09-11 at T11.F09 it is 129 cards and 60 charts over 14,000 pixels, and the Goal worlds tab is three identical 21-card stacks, one per world, so the same indicator is never seen across worlds side by side. Its groups follow data sources — work counters, wall clock, population, structure, memory, neighborhood — not questions. Its five headline tiles per world are final population, births, food-type-1 eat share and two barrier-blocking rates: two of five headlines are a T12.F04 verification artifact and none is a diversity or cognition indicator, so the north star is not on the tiles. Deltas read "+28.3% vs T13.F01" and "−54.2% vs T13.F01" on one run per world with no spread, no cause and no single-run label. Only drift depth draws its floor; memory sensitivity says "a rise is the signal" and marks neither what a rise would look like nor its exposure denominator. Six per-creature-tick work-counter charts repeat per world — eighteen charts of compute on the ecology tab — with the same visual weight as the indicators. The redesign: (1) lead with the five questions the success definition asks, in order — is the world alive; how many ways of living, for how long; is cognition present and paying; is the substrate still evolvable; what did this closure cost — one section each, the last being compute; (2) headline tiles become the answers to the first four, chosen from the goal indicators and the T14 readings as they land, with barrier and blocked-move rates moved into a per-world detail view; (3) every indicator is a small multiple across Orchards, Canyon and Confluence in one row, with the historical goal-v1 series drawn as a labelled break rather than a separate tab, so a series boundary is visible in the chart and not hidden by navigation; (4) every chart draws its floor or first-reading reference where one exists, and prints its exposure denominator or seed spread beside the value; (5) a delta computed from one run per world is labelled single-run and is never rendered as if it carried a spread; a "not measured" reading stays drawn as such, never as zero; (6) each T14 row that lands adds its reading to the section it answers — deaths by cause and energy flows under "alive", the clade profile, loss curve and occupancy grid under "ways of living", reproductive success by class, sensor reach and changed plasticity under "cognition" — under the same standing rule that puts an indicator in the goal profile with the feature that introduces it; (7) keep what already works: every chart keeps its JSON-path subtitle, the table toggle, the hover readout with host and date, and the tick-zero map. The spec fixes the section order, the headline set and the reference-line rules before any chart is moved, and re-assesses every existing card against one test — which question does it answer, and does the reader need it to answer that question — dropping the ones that fail. The spec is the place to decide whether the historical gate profile keeps its own view or folds into the compute section.
- **Pull-forward trigger, T05.F03.** Trophic edges by clade — predator clade by prey clade kill counts — are T05.F03's content and remain there. Predation already exists and its counters reach the server, so the reading is cheap now; if F07 shows predation is a way any surviving clade makes its living, that is the trigger to schedule T05.F03, not a reason to absorb it here.
- **Prediction, T02.F01.** Prediction is acting ahead of a stimulus and has no telemetry-level reading until the world has a cycle to be ahead of. When T02.F01 lands seasons, the reading is the phase relationship between a clade's intake and the food cycle, and under the standing rule it ships with T02.F01 as that feature's indicator. This track records that fact so the reading is not invented here without its cause.
- **Not in this track.** New interventions, assays, comparators or campaigns; behavioral strategy descriptors, strategy counts, niche-overlap and ecological diversity measures derived from F07's raw rows, which are T01.F04 and T01.F06 in the deferred proof phase; per-lineage *cumulative* telemetry inside `WorldTracking`, which the audit refuted because that struct sources world totals by deliberate design (F07's terminal per-clade table is bounded and separate); trophic edges by clade, which are T05.F03; a prediction reading, which needs T02.F01's cycle; anything that changes a rate, a default or a charge.
- Execution priority is unset. These rows are not in the master roadmap's order of new starts and none is scheduled; that remains the user's decision. Verification and closure follow `docs/workflow.md` unchanged, and feature specs stay flat and are written just in time.
