Single-pass inline review of `git diff main...HEAD` (four angles: reuse,
simplification, efficiency, altitude); behavior unchanged, the identity pin
above rerun after the edits.

| File | Change |
| --- | --- |
| `crates/v3-core/src/mutation/engine/mod.rs` | per-unit branch sums `u32::from(rng.gen_bool(rate))` over the units instead of `filter(...).count() as u32`; same one `gen_bool` per unit in the same order, no `usize -> u32` cast |
| `crates/v3-core/src/neighborhood/drift.rs` | `supply_rule` reads the four legacy fields from the config it receives instead of cloning the whole config through `forced_legacy_supply` first (the forcing touches none of those fields); output string byte-identical, pinned by `v3-cli bench::run::tests` |

Skipped: consolidating the ~40 test sites that add
`per_unit_supply_enabled = false` before `mutation_probability` (the pattern
predates the feature; one line per site); a shared `MutationConfig` helper
behind `forced_legacy_supply` and `proposal_mutation_config` (two callers with
different base configs, and the spec names `proposal_mutation_config()`); the
`// per_unit_supply_enabled: bool, no normalization needed.` comment in
`normalize` (it follows the file's existing convention for boolean fields);
the frontend `Rate / Unit` `max: 0.1` against the backend clamp to `[0, 1]`
(a product choice, not a cleanup).
