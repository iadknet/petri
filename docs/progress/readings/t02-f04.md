## Observations

- The spec's recovery invariant cannot hold for arbitrary `u32
  recovery_ticks` in f32: past roughly `1e7` the step `1 / recovery_ticks`
  falls under half an ulp near 1.0 and `m + step == m`. Normalization caps
  `recovery_ticks` at `MAX_GRAZING_RECOVERY_TICKS` (10_000), the same
  constant the property tests draw from, so the accepted domain and the
  tested domain are one; the panel field and the reference rows carry the
  same bound.
- `seed_density` resets the grazing layer to 1.0 alongside the occupancy
  depletion layer; the spec is silent on world seeding, and a freshly seeded
  world has no bites.
- The goal-report readings live on `WorldTracking` (`grazing_modifier_mean`,
  `grazed_cell_share`, per-type `Vec<String>` beside `food_density_total`)
  rather than on `TrackedFractions`, because they are final-tick state, not
  ratios of the tracking totals. Their comparison rows follow
  `typed_eat_share_type_{i}` as the spec asks.
- `docs/reference/v3-tick-orchestration-spec.md` Phase 0 sub-steps 1 and 2
  now name the grazing recovery step; the spec listed only the three other
  reference documents, but the canonical Phase 0 order would otherwise have
  been untrue.
