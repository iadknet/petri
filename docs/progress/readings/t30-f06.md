# T30.F06 — Actions as Transactions: readings

## Options weighed at planning (2026-10-26)

A refactor inside one crate: the options are shapes of the existing code,
not external tools. Local evidence: `simulation/tick.rs:852-1346`
(executors, flooring, removal), `simulation/actions/{mod,giving,predation,reproduction}.rs`,
`creature/action_log.rs`, `simulation/outcomes.rs:53`,
`v3-server/src/transport/action_log.rs`, `scripts/architecture-debts.txt`.

| Decision | Options | Chosen and why |
| --- | --- | --- |
| The one outcome vocabulary | (a) today's ten log classes, with the mechanics enums (`PredationActionResult`, `GiveActionResult`, `ReproductionActionResult`) returned beside them; (b) a nested enum, one inner enum per action kind, the log and wire keyed by `kind:inner`; (c) one flat `contracts::ActionOutcome` holding every distinction today's records make (ten log classes plus `NothingToTake`, `NothingToGive`, `LitterTooSmall`), the per-action key enums kept as total projections for the run totals and metric attributes whose key strings T21.F02 fixes | (c): one value per action (the row), every exported key string unchanged (telemetry families, bench tracking), the wire enum stays a flat string enum the frontend already renders; (a) is two vocabularies in one return, (b) re-keys the log, the diagnostics and the frontend for no gain |
| Where the run totals are bumped | (a) in mechanics, which then need `&mut SimStats`; (b) in the scheduler's commit step from the applied result | (b): the row says the totals derive from the result; mechanics then need no `SimStats` and no `Simulation` |
| What the log stores | (a) the whole result including the `f64` attempt effort (entry 40 bytes, capacity 500 per creature); (b) the outcome and amount, entry stays 32 bytes | (b): the effort is consumed by the failed-effort derivation and nothing reads it from the log; the log's layout, capacity and memory are unchanged |
| The span-0 birth | (a) `spawn_child` called inside the reproduce transaction, so mechanics take `&mut Simulation`; (b) the transaction returns the conception (target, litter) and the scheduler calls `spawn_child` at once | (b): the birth path is T29.F01's (G4) and already a scheduler call for delivered litters; the RNG draw order is unchanged because nothing draws between the transaction's return and the spawn |
| The victim's removal | (a) inside `apply_steal_energy` as today; (b) reported by the result and settled by the scheduler through `Simulation::remove_creature` | (b): the row's one removal-settlement path; the attacker's own death already settles there |
