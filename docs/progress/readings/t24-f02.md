## Options weighed at planning (2026-10-07)

| Decision | Chosen | Against | Why |
| --- | --- | --- | --- |
| Random source for food draws | A keyed per-cell stream: `splitmix64` finalizer over (run key, tick, type, purpose, index), one round per cell, unbiased multiply-shift to a range; `splitmix64` already exists in `crates/v3-core/src/creature/identity.rs` | (a) a Philox crate (`rand_philox`-style counter RNG); (b) `SmallRng::seed_from_u64(key)` per cell; (c) keep `sim.rng` and pre-draw a per-cell table sequentially | (a) is a new dependency the track Notes exclude for a 20-line function; (b) seeds xoshiro256++ (four splitmix rounds and state) per cell for one draw; (c) keeps a sequential full-grid draw pass on the timed path and keeps food on the run RNG, so later draws still shift whenever food's draw count changes |
| Spread form | Claim then gather: the claim pass stores `own`, `local_base`, `local_after_inhibition` and the pick per cell; the gather sums the N, E, S, W contributions whose pick is the cell | (a) scatter with atomics or per-thread buffers merged in order; (b) gather recomputing each neighbour's pick and local terms (the track Notes' sketch) | (a) `f32` atomic adds are order-dependent, and per-thread buffers cost `threads × grid` memory plus a merge pass; (b) recomputes up to four neighbours' fertility, inhibition and depletion terms per target, which eats the speedup margin; the claim pass keeps every term computed once |
| Unit of parallel work | Rows (`par_chunks`/`par_chunks_mut` of `width`), partials per row reduced in row order | per-cell `par_iter` with `fold`/`reduce` (thread-dependent reduction tree); per-chunk partials sized by thread count | both give results that depend on the pool; a row is a fixed unit whatever the pool |
| Scratch buffers | Retained in `FoodResource` in place of the three unused scratch fields | per-tick `vec![0.0; cells]` as today | a zeroed 10 MB allocation per type per tick is a sequential remainder (page faults) against a target of about 30 ms per goal tick |
| Recovery spawns | Sequential on the keyed stream | parallel | about 2,560 attempts at the default rate; the Notes allow sequential |
| Speedup instrument | `bench --profile sweep` at 1600², 100 ticks, seed 11, `--threads 8`, reading `environment.phase_wall_clock_ms_per_seed[0].food_growth_ms` per tick, 6 interleaved pairs under `scripts/bench-wait`, 900 s cap, verdict at ≥ 4 pairs on the median ratio | (a) the goal profile's `food_growth_ms` against T24.F01's (unpaired, 11 min per side); (b) `profile_ticks` (no phase split, non-default config); (c) `scripts/telemetry-overhead`'s pair machinery (compares builds of one commit, 300 s cap that went inconclusive four times at T24.F03) | the sweep report carries T24.F03's phase per seed, one run is about 15 s idle, and in-process phase time makes the pair ratio robust to load both sides share |

Research scope: local evidence (the code at 3b904894, the track Notes, the
T24.F01 and T24.F03 specs and readings, `scripts/telemetry-overhead`'s pair
method) plus the counter-based RNG design the Notes cite (Philox, Salmon et
al. SC11): a keyed hash of (key, counter) is the standard way to make draws
independent of scheduling; the splitmix64 finalizer is the usual small-footprint
choice for that role in-tree.

## Pass decomposition on 3b904894 (implementation task 1, 2026-10-07)

Instrument: a scratch harness (not committed) on a release build with
`telemetry-seams`: `seed_simulation(SimulationConfig::default(), 11)` (1600²,
10,000 founders, one food type), one warm-up tick, then the
`last_tick_food_passes` seam summed over 10 ticks, global pool (8 threads),
each run alone under `scripts/bench-wait`. Host load (`uptime`, 1/5/15 min)
6.39/5.39/5.03 before run 1 and 5.86/5.31/5.01 before runs 2 and 3, with
`mediaanalysisd` at about 200% CPU throughout.

| Pass (ms per tick) | Run 1 | Run 2 | Run 3 |
| --- | --- | --- | --- |
| `depletion_recovery` | 6.902 | 6.919 | 7.170 |
| `grazing_recovery` | 2.671 | 2.715 | 2.715 |
| `inhibition_sums` | 3.302 | 3.419 | 3.366 |
| `density_total` (type 0) | 2.510 | 2.497 | 2.534 |
| `growth_spread` (type 0) | 31.315 | 30.799 | 32.372 |
| `write_back` (type 0) | 4.109 | 4.106 | 4.403 |
| `inhibited_count` | 0.049 | 0.046 | 0.060 |
| `food_growth` phase | 50.866 | 50.507 | 52.629 |

`growth_spread` dominates (61%), then the three depletion loops (14%) and
write-back (8%). The passes sum to the phase within 0.01 ms, so no sequential
remainder sits outside the spans; `recovery_spawns` does not run on the default
world (the type is above its floor). Changes the readings led to, all inside
the T24.F03 span boundaries:

| Change | Why |
| --- | --- |
| `depletion_recovery`'s decay, deposit and mean loops fused into one row-parallel pass | each cell's value depends only on itself, so one sweep replaces three over the second-largest region |
| The claim buffers `own`, `local_base`, `local_after_inhibition` and `pick` stored as one array of 16-byte `ClaimCell`s | the gather reads all four fields of a neighbour together, so one cache line serves each source |
| The gather computes the target-side fertility, penalty and multiplier only when a neighbour's pick is the cell | most cells receive nothing; the claim already computed the source side once |
| The inhibited-flag reset runs inside `inhibition_sums`, where the per-tick `vec![false; cells]` was | the flags are retained (invariant 5) |

Post-change reading (one run, same harness and host, load 4.99/5.73/5.52; an
indication, not the criterion-3 measurement): phase 14.725 ms per tick;
`depletion_recovery` 0.551, `grazing_recovery` 0.744, `inhibition_sums` 0.777,
`density_total` 0.454, `growth_spread` 11.319, `write_back` 0.766,
`inhibited_count` 0.109.

## Speedup pairs (track criterion 3, 2026-10-07)

Method as predeclared in the spec's Performance section: parent `v3-cli` built
`--release` from a scratch `git worktree` of 3b904894 (removed afterwards),
feature `v3-cli` built `--release` from the feature worktree at the final code
of this pass, both rustc 1.93.0; each run under `scripts/bench-wait`, timed by
`/usr/bin/time -p`, workload `bench --profile sweep --width 1600 --height 1600
--founders 10000 --ticks 100 --seeds 11 --threads 8 --telemetry off`. Reading:
`environment.phase_wall_clock_ms_per_seed[0].food_growth_ms` divided by
`deterministic.per_seed[0].ticks` (100 in every run). Order alternated pair by
pair, parent first in odd pairs. One attempt; 1-minute load 4.49 before
(5-minute 7.81) and 5.69 after (5-minute 7.13).

| --- | --- | --- | --- | --- | --- | --- |

| 2 | feature, parent | 40.636 | 12.936 | 0.3183 | 21.16 | 19.22 |
| 3 | parent, feature | 40.218 | 13.391 | 0.3330 | 20.76 | 20.11 |
