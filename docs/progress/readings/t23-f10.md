## Scratch-stack verification (2026-10-01)

Run on the final `scripts/telemetry-window-store`. Portless scratch stack
`petri-telemetry-f10scratch` (its own volume; a Compose override `ports:
!reset []`, `docker port` lists 0) beside the running `petri-telemetry`
stack, which was not stopped, written to or bound. Records were posted as
OTLP/HTTP JSON from inside the scratch container, the name in an
`event.name` attribute as the exporter sends it; the job ran as `docker
compose run --rm --no-deps -T window-store --once` with
`PETRI_WINDOW_STORE_CAP_BYTES=920000`. Indexes were read with `sum by
(petri_window)` metric queries in 400-index slices, delete requests with
`GET /loki/api/v1/delete`. Loki serves records older than 3 h only from
flushed chunks, so R4 was flushed (`POST /flush`) before pass 1.
