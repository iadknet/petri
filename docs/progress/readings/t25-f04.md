## Options weighed at planning (2026-10-15)

Research base: the design note (`docs/strategy/edge-groups-and-learning-design-2026-10-13.md`, version 3; superior-colliculus register and HybrID prior art in its §5 and Sources) and the code as read on 2026-10-15. No external search was repeated: the user mandated the design, and the spec's job is to apply it well.

| Question | Options | Chosen | Why |

| Where the pairs are declared | (a) `WorldInputKey::direction_pairs()` in `contracts::inputs`, written in terms of the `*_idx` modules moved there from `sensors/perception.rs`; (b) a table in `cgp/group.rs` naming raw sub-indices; (c) leave the modules in `sensors` and declare pairs by raw index | (a) | Design note D12 ("pair metadata lives in `contracts::inputs` beside `compound_width`", the reducers as the writer); a pair written as `food_idx::GRADIENT_X` cannot drift from the layout; the re-export keeps every reader unchanged. |

| Member coordinate | (a) `(field, direction)`, direction read from the sink the member sits on; (b) derive the sink from the source as `Ring` does | (a) | An `x` member sits on six sinks with one source, so the source cannot name the sink; I10's in-sink key `(GroupId, sub_idx)` stays unique because `x ≠ y`. |
| Zero-pattern members | (a) forbid them in `validate_graph`; (b) valid but never created (12 of 16) | (b) | The note's I4 wording; relocation moves direction and offset together so none arises; forbidding them would make I4 offset-dependent for no behavior gain. |
