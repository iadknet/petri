## Options weighed at planning (2026-09-30)

| Decision | Chosen | Against | Why |
| --- | --- | --- | --- |
| Holding records until the last timed region ends | F01's held worker (`Shared.held`, `take_batch` waits until `release`), promoted from a `cfg(test)` hook to `Telemetry::start_held` and `release` | capture into a plain buffer with explicit timestamps and start telemetry only at the end | held keeps F01's per-run accounting, stderr lines and queue bounds unchanged and needs no `emit_at`; the idle worker thread and HTTP client cost nothing until a batch is taken, and the spec defines exporter activity as taking, encoding and sending |
| Unit of record for assays and the lab | one measurement per invocation (`measurement.started`/`measurement.ended`) with the stored summary's totals as the body | one `run.*` pair per simulation inside the assay or lab loops | those simulations number hundreds to thousands per invocation (lab: population × generations × replicates × scenes), the queue holds 2,048 items, and the loop rule forbids in-loop capture; D2 names the summary's totals, which are invocation-level |
| Benchmark seed runs | F01 `run.started`/`run.ended` per seed at the seed's own boundaries, `run.ended` carrying the summary's `PerSeed` totals as attributes | (a) invocation record only; (b) an F02 run-end snapshot per seed | a seed run is one simulation from seed to end, the track's definition of a run, and gate and goal hold three; (a) loses that; (b) queues about 195 KB per seed (F02 readings) and exports 2,900 series the summary does not carry, wider than D2 |
| Totals carried | the stored summary's own blocks verbatim (`deterministic.totals`, the assays' counts, the lab's `timing`) as a compact JSON body plus `petri.summary_path` and the raw identity | a new metric family per command | D2: "the totals their stored summary already carries"; a log record with the path lets a dashboard reading be reproduced from the stored file, which the track's not-closure-evidence note requires |
| Fixture workload | `bench --profile sweep` at 32×32, 16 founders, seeds 11 and 22, 20 ticks, under a second per run | the gate profile; `v3-lab run --quick` (about 60 s) | the fixture runs three times inside `make check`; the sweep profile runs no neighborhood, drift or observation region but does run the seed loop and the report and summary writes, so every capture point and the release point are exercised |
| Lab boundary | `cli::execute` returns a plain `Measurement`; `main.rs` alone calls `v3_telemetry` | emit from the library behind the feature | the track's Boundary note: `v3-lab`'s library depends on no telemetry SDK type; the library already names only `Switch` |
| Overhead check | not applicable, with the reason predeclared | run F01's method on `v3-cli run` | the diff leaves the check's workload untouched, so the reading would measure host noise; the bench's own wall-clock fields exclude the capture points by placement, which the fixture's bracketing assertion and the reviewer check |
