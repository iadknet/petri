| Question | Options | Chosen, and why |
| --- | --- | --- |
| Type generator | `ts-rs`; `typeshare`; `specta`; a hand parity test per type | `ts-rs`, the user's 2026-10-25 decision (typeshare emits neither 64-bit integers nor internally tagged enums; specta is a release candidate). ts-rs 12 supports `tag`, `rename_all`, `skip_serializing_if`, `flatten` and `default`; `TS_RS_LARGE_INT=number` renders 64-bit integers as `number`; `export_to_string` renders without touching disk. |
| How the generator runs | `#[ts(export)]` (ts-rs generates a test per type that writes to `TS_RS_EXPORT_DIR` on every `cargo test`); one explicit v3-server test over a listed root set that renders with `export_to_string` and compares | the explicit test: `cargo test` must never rewrite committed files (the row: "rewriting them only on an explicit flag"), and one list of roots is one place to review coverage. |
| Committed file format | raw ts-rs output with Biome's formatter ignoring the directory; Biome-formatted files with a format-insensitive comparison | Biome-formatted (the row), the test comparing declarations with whitespace and member separators normalized; any added, removed, renamed or retyped field, variant or type still fails. |
| Core's exempt types (`Direction`, `Position`, the id types, the config schema) | a `ts` cargo feature on `v3-core` carrying an optional `ts-rs` dependency and `cfg_attr` derives on the exempt types only; server mirrors | the feature-gated derive: a config mirror would duplicate about forty structs by hand, the very copy the row removes; the derive is a build-time attribute off by default, so `--no-default-features` and every binary are unchanged. Every other core type stays underived so a core struct inside a wire type fails to compile, which is the row's enforcement. |
| Shape of the brain view | (a) keep `genome` + `mesh_annotations` + `graph_weights` behind server copies; (b) one `brain` tree (structure, annotations and every resolved edge fact) and one per-poll `learning` payload (the runtime's learner and scale views); (c) one merged tree refreshed on every poll | (b): the split follows the core's own owners (genome structure once per life, runtime learned state per tick) and keeps the inspector's poll as light as today's `graph_weights`; (a) keeps the layout as the API (G17); (c) re-sends the structure every poll. |
| VM instruction on the wire | a mirrored server enum, one variant per opcode; an opcode-and-operands record | the mirror: every other sampler DTO is a mirror with an exhaustive match, and the generated union is what `vmInstructionFormat.ts` and `runtimeIoSemantics.ts` already switch on by variant name. |
| Input reference on the wire | mirrored nested enums (`InputReference`, `WorldInputKey`, two introspection keys, the decision references); one flat record (family, key name, food type) | the flat record: the frontend already flattens to `{key, typeIdx}` and keys its catalog fixtures by the key name; the nested mirror would copy five enums for nothing. |
| Action log entry | leave `ActionLogEntry` on the wire (`#[ts(skip)]`); a server entry mirrored from today's fields | the mirror: a core struct in a `TS` type does not compile, and the F06 note already provides for F01 landing first; F06 later builds the same entry from the applied result (G18). |
| Benchmark profile | `none` (frontend and transport); `gate` | `gate`: the diff adds fields to the runtime's learned view and read APIs to the genome, so the gate's pins are the proof that no trajectory moved, at seconds of cost. |
