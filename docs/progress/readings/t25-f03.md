# T25.F03 — Ring Groups Replace Ring Projections: readings

## Options weighed at planning (2026-10-15)

Research base: the design note (`docs/strategy/edge-groups-and-learning-design-2026-10-13.md`, version 3 after three Codex rounds and nine Opus facet reviews; HybrID and Eph/ephrin prior art in its §5 and Sources) and the code as read on 2026-10-15. No external search was repeated: the user mandated the design, and the spec's job is to apply it well.

| Question | Options | Chosen | Why |
| --- | --- | --- | --- |
| How a projection becomes a group | (a) a converter that rewrites a `RingProjection` into a `Ring` group on load and at birth; (b) delete the type and its list outright, groups in their place | (b) | Design note §8 F03 ("no converter"); no backward compatibility is a project rule (user, 2026-10-11); F02 already charges nine units so the replacement is size-neutral by construction. |
| Member weight at run time | (a) a table of one `f32` per sink edge built once in `GraphRuntimeState::for_genome`; (b) compose `scale + own_weight` in the sink loop with a membership branch and a group lookup per edge | (a) | Design note §3 ("the hot path reads one table entry per sink edge"); the loop stays branch-free, and F06's `applied_weight` falls back to the same table, so the table is built once rather than twice. |
| Commit shape | (a) one commit; (b) a text-only identity commit then the behavior commit | (b) | Track Notes: "F03 and F06 land a text-only commit (genome identity) before their behavior commit"; design note §7 "Determinism and pins" gives the restoring check ("the hash without genome text is unchanged"). |
| Inferred ring refinement | (a) keep `GroupKey::Ring` beside explicit groups; (b) delete it (D7) | (b) | An inferred ring beside an explicit one would be two mechanisms for one concept; the explicit group's step is `AlterGroupScale`; `Slots` stays for F08 to decide. |
| `groups` in JSON and `Debug` | (a) always present; (b) omitted from JSON when empty, printed by `Debug` unconditionally | (b) | JSON stays small for the common no-group genome and `deny_unknown_fields` plus `default` loads either form; `Debug` covers every heritable field (I9) and the text commit absorbs the one-time fingerprint change. |
| Protocol version | (a) one bump at commit 1 (`v3alpha6`) covering the key rename, `groups` and `graph_weights`; (b) two bumps | (a) | Both commits land in one feature on main; the frontend is rebuilt with the server; a §2 history line names the whole shape change. |
| Blocked-move fraction of carriers vs non-carriers (design readings) | (a) add a carrier-keyed per-creature instrument; (b) drop it | (b) | No track row or success criterion names it, no summary block carries a per-creature carrier key, and the user prefers no verification machinery beyond what a decision needs (2026-09-07, 2026-10-12). |
| Gate validation of the new invariants | (a) `validate_graph` in the mutation gate under its own skip reason and counter; (b) container `debug_assert`s only | (a) | Design note D5; the counter staying 0 in the engine-level proptest and in the goal runs is the evidence that no operator breaks an invariant in release builds. |
