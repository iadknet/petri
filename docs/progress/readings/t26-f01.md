# T26.F01 — One Body Record and Body Rules: readings

## Options weighed at planning (2026-10-20)

Local precedent first: `CreatureIdentityState` (`creature/identity.rs`) is
already a small `Copy` domain record with `founder` and `inherit`
constructors; the lab (`v3-lab/src/eval.rs:36-54`) and the server
(`CreaturePhenotypeResponse`) each model the phenotype triple as a struct.
External guidance checked: the Rust API Guidelines and clippy's
`too_many_arguments` lint (default threshold 7, which both constructors
exceed under `#[allow]`) recommend a parameter struct over positional
arguments; a builder is for optional or defaulted fields, which the record
has none of.

| Question | Options | Chosen, and why |
| --- | --- | --- |
| Record shape | parameter struct with public fields; builder; keep positional arguments and add a fifth | Struct: every field is required and `Copy`; a builder adds ceremony with no optional field; positional arguments are the deficiency (53 sites, two `#[allow(clippy::too_many_arguments)]`). |
| Phenotype nested or flat | `HeritableBody { phenotype: Phenotype, identity }`; six flat fields on the body | Nested: the triple already exists as a type in the lab and the server, and `mutate_phenotype` takes and returns exactly it; the lab type is deleted rather than kept beside the core one. |
| Who owns the mutation gate | reproduction passes `applied_events > 0`; the body reads the `MutationSummary` | Reproduction passes a `bool`: the identity spec's ownership split (reproduction owns when, the domain owns how) is kept, and the body record owns only the order of the two draws. |
| Where the cap step lives | `simulation/actions/mod.rs` beside `pay_effort`; `simulation/energy_accounting.rs` beside `applied_debit`; a `CreatureState` method | The action layer (Codex round 1 F2): the step mutates stored energy, and `energy_accounting.rs`'s header contract (T14.F03, `083b3372`) is "observations that never drive execution"; the booking arithmetic (`applied_debit`) and the cap value (`energy_cap`, which F02 reads from the body) stay where they are. |
| Cap step arithmetic | the comparison form `if energy > cap` (predation today); `min`/`clamp` (eat today) | Comparison: it is predation's exact form, and with eat's floor also written as a comparison every input gives today's result at every site: `+∞` is capped, `−∞` floored to zero at eat, `NaN` left `NaN` (as `clamp` leaves it). The planning claim that "a non-finite energy passes through unchanged" was wrong for `+∞` and `−∞` (Codex round 1 F1); the characterization tests cover the three cases. |
| Where the move rule lives | `CreatureState::move_effort(&self, &EnergyConfig)`; `EnergyConfig::move_effort(&self, &CreatureState)` | On the creature: the config module must not depend on `creature::state`, and F02's factor reads the body's capacity. |
| Slow tier | `run`; `not run` with the lab change argued trivial | `run`: the workflow's table names any `crates/v3-lab` change, and the tier's recruitment-paths readings are a second pins-unchanged reading for free. |
