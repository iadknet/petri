## Focused tests

`crates/v3-core/src/simulation/actions/mod.rs` (`tests`), through
`apply_reproduce` on the founder at age `min_reproduce_age`, default config:

| Test | Branch | Fixture |
| --- | --- | --- |
| `apply_reproduce_min_energy_rejection_does_not_charge_reproduce_cost` | `energy - cost < min_reproduce_energy` | energy 30.0, request 20.0 |
| `apply_reproduce_infeasible_transfer_rejection_does_not_charge_reproduce_cost` | `energy - cost < transfer` | energy 50.0, request 100.0 |
| `apply_reproduce_non_positive_transfer_rejection_does_not_charge_reproduce_cost` | `transfer <= 0.0` | energy 80.0, request 0.0 |
| `apply_reproduce_birth_pays_cost_then_transfer_as_two_subtractions` | accepted | energy 80.0, request 20.0 |

The three rejection tests share `assert_energy_rejection_is_free`: parent
energy bit-identical, `pending_death_cause` unchanged,
`action_charges.reproduce` and `parental_transfer_debit` unchanged,
`reproduction_actions_rejected_total` +1 and the
`RejectedEnergyConstraints` reason count at 1. The accepted test computes
`cost` as the engine's product expression (`reproduce_charge`) and pins the
parent at `(energy - cost) - transfer` bit-exactly, the two flow debits as
`applied_debit` of each step, and the child at `transfer`; on the red run
(tests written, engine unchanged) it and the age precedent were the two
passes against the four rejection-side failures, so it is the
bitwise-stability witness for invariant 3.

`crates/v3-core/src/simulation/actions/reproduction.rs` (`tests`):
`energy_rejected_attempts_leave_the_reproduce_flow_at_zero` (invariant 4):
200 founders on 48x48 for 40 ticks with `min_reproduce_energy =
max_energy + 1`, so every attempt is an energy rejection; asserts
rejections > 0, spawned 0, and `action_charges.reproduce` exactly 0.0
(pre-feature value on the red run: 263.601).

`crates/v3-core/src/simulation/tick/tests/energy_accounting.rs`:
`reproduce_below_cost_rejects_free_and_records_no_crossing` replaces the
Reproduce arm of
`every_base_action_crossing_keeps_its_cause_through_the_action_floor`;
that arm (energy 1.0, cost 2.0) relied on the charge landing before the
gate, and acceptance now requires `energy - cost >= transfer > 0`, so the
reproduce charge can no longer cross zero.
