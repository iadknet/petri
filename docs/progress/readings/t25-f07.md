# T25.F07 — Group-Scope Learning: readings

## Options weighed at planning (2026-10-19)

| Decision | Options | Chosen | Why |
| --- | --- | --- | --- |
| Applied weight of a member on a learning graph | (A) compose on read from the slot list: `own + scale × pattern`, the learner holding each slot's pattern and scale reference; (B) a per-backend applied-weight table refreshed after every learning write | A | no derived cache to keep in sync; one multiply-add per weighed edge; the resolver, the view and the executor share one formula (invariant 3). B would add a second source of truth the F06 design removed. |
| Static members of a learning group | (A) a passive set the learner weighs through the learned scale; (B) refresh the F03 genomic sink table on scale writes | A | B is option B above in disguise; the passive set costs one comparison per edge on learning graphs only. |
| Group credit | (A) `Σ pattern × Δ`, bounded once (D4, user decision 2026-10-13); (B) the mean of members' Δ; (C) each member learns its own weight and the scale stays genomic | A | user decision; A is tied-weight credit (the change of a shared parameter is the sum over its instances, each through its pattern), so a `Ring` member contributes Δ unchanged and a negative-pattern member's contribution carries the opposite sign of its Δ while its own applied weight still moves with its rule. |
| A group learner's own weight | (A) no learned own quantity: genomic own, seeds on its row ignored, captured as `None`; (B) a stored but unused learned own weight carried through capture | A | B would store and inherit a value execution never reads, which could reappear after a scope change or a detach (round-1 B3). |
| Where scope lives | (A) `Membership.scope` (design note §3); (B) `PlasticityConfig.scope` | A | scope is a property of membership, exists on a static member and survives `DisableHebbian`; `EnableHebbian` at group scope then needs no scope draw. |
| Serde of the new fields | (A) always written, no default; (B) `default` + `skip_serializing_if` | A | a member always has a scope and a group always an inheritance flag; no hidden default, identity of grouped genomes re-pins once (predeclared), format 5 refuses older files (no backward compatibility, user 2026-10-11). |
| Commits | one; or text-only then behavior | two | one cause per commit for the re-pins (track Notes): commit 1 moves grouped-genome identity only, commit 2 every Graph draw. |
| Counters for a moved scale | one change per scale write; one change per contributor | per contributor | keeps `changes ≤ updates` and the "share of updates that change a weight" panel meaningful for groups. |
| First-update snap reading (design note §8) | (A) a census gauge "scale slots whose genomic scale is outside the bound"; (B) a cumulative counter at the write that snaps | B | exact: only the first write of an unseeded scale can find its stored value outside the bound, a zero-`Σ` event included; A cannot tell a snapped slot from one awaiting its first event (round-1 B5). |

Sources read 2026-10-19: Larsen & Sjöström 2015, Curr. Opin. Neurobiol.
35:127, [PMC5280068](https://pmc.ncbi.nlm.nih.gov/articles/PMC5280068)
(abstract verified at source: plasticity "is specific to the synapse type,
a concept we denote synapse-type-specific plasticity"); Rumelhart, Hinton &
Williams 1986, Nature 323:533 (tied weights; summary, not fetched); Risi &
Stanley 2010, "Indirectly encoding neural plasticity as a pattern of local
rules", SAB 2010 (a pattern-generated local learning rule shared by the
connections one program builds; summary, the source was unreachable on
2026-10-19). The design note §5 carries the track's sources.
